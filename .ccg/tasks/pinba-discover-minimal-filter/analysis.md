# CCG 综合分析：发现页最小筛选

## GPT 5.5 后端结论

- Memory、CloudStore、Mock 已具备 `type + city + district` 精确 AND 过滤，不需要改查询或游标实现。
- 当前缺口在 `activity.list` API 边界：`type/city/district` 被直接透传，必须增加专用公开列表校验。
- `type` 限定现有三类；`city` 限定上海试点；`district` 限定发布页已有六区；“全上海”是客户端展示值，服务端必须拒绝该字符串并要求省略字段。
- 筛选变化必须由客户端使用 replace，不传旧 cursor；append 继续原样透传服务端游标。
- Mock 必须同步真实服务的验证错误码与组合过滤行为。

## Web Gemini 3.7 Flash 前端结论

两份结果一致同意：

- 使用原生 `<picker mode="selector">`，不增加第二条横向 Chip，不引入第三方组件。
- 顶部城市胶囊静态显示“上海试点”，不制造只有一个选项的城市 Picker。
- 只有 `currentType`、具体 `district`、`appliedKeyword` 计入生效筛选；未提交的 `keyword` 草稿不计入。
- 区域切换保留类型与已应用关键词，立即 replace；清除筛选同时重置类型、区域、输入草稿和已应用关键词。
- 有筛选的空状态主动作改为“清除筛选”。

两份结果唯一差异是 Picker 位置：一份推荐场景 Tab 后独立筛选条，一份推荐塞入搜索栏左侧。

## 主会话综合决定

- 采用独立筛选条，放在场景 Tab 与列表标题之间。
- 原因：搜索栏已有搜索图标、弹性输入框和搜索按钮；在 320px 或大字号下加入第四个控件会显著压缩输入区。独立筛选条增加少量纵向高度，但更稳定、语义更清楚。
- 筛选条左侧为 88rpx 区域 Picker，右侧仅在有生效筛选时显示 88rpx“清除筛选”。使用 flex-wrap 防止极端字号挤压。
- 网络错误仍以“重新加载”为 empty-state 主动作；筛选条的“清除筛选”保持可见，因此无需给错误组件扩双按钮。
- 无筛选且真正无数据时保留“去发布”；有筛选且无结果时优先清除。
- 客户端新增共享试点区域配置，供发现页、发布页和 Mock 使用；Cloud Function 保持自身常量边界，避免跨包依赖。

## 范围

- 不做 GPS、地图、距离、排序、多城、区域多选、费用/强度/时间高级筛选。
- 不重做当前服务端 raw-offset cursor；客户端继续将其视为不透明值。
