# 发现页最小筛选需求

## 目标

在既有“场景 Tab + 关键词搜索 + 游标分页”基础上补齐区域选择，让上海试点用户能用最小成本缩小活动范围，同时保持游客零登录、零定位授权和稳定分页。

## 当前事实

- 发现页已有场景 Tab、关键词输入与显式搜索、分页、弱网重试、截止状态刷新。
- 客户端始终发送配置中的演示城市“上海”；城市胶囊当前不可交互。
- 服务端、Memory、CloudStore 和 Mock 已支持 `city`、`district` 精确过滤。
- 发布页当前允许浦东新区、徐汇区、杨浦区、静安区、黄浦区、长宁区。

## 本阶段边界

- 增加“全上海 + 现有六个发布行政区”的单选区域筛选。
- 类型、区域、已应用关键词任一生效时，列表和空状态明确表达处于筛选状态。
- 清除筛选一次恢复全部类型、全上海和空关键词，并发起 replace 请求。
- 区域变化必须重置游标、抢占旧 append/replace，并与现有分页、举报隐藏和截止刷新兼容。
- 不获取 GPS，不增加距离排序、地图、多选、高级费用/强度筛选。
- 保持 Mock 与真实服务契约一致；如外部分析确认需要，补公开列表过滤字段的安全校验。

## 验收

- 选择行政区后，请求携带精确 `district`；选择“全上海”时不发送 `district`。
- 清除筛选后所有筛选状态与搜索输入同步复位。
- 筛选切换时晚到响应不能覆盖新结果，分页游标从首屏重新开始。
- 320px、小屏、大字号和读屏下筛选控件可操作，热区不小于 88rpx。
- 全量自动化、项目检查、CCG 分域复审通过。
