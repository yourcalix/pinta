# 实施计划

## 决策

- 普通乘客是所有已完善资料用户的基础能力；审核通过司机是在此之上的附加能力。
- `users.onboarding.roleIntent` 只用于首次引导，不参与授权。
- 司机申请使用独立记录与状态机；生产环境绝不自动审核通过。
- 本轮实现结构化敏感字段的边界、脱敏 DTO 与私有文件引用契约；真实生产密钥与人工审核后台仍作为上线门禁，仓库不放密钥。
- 审核驳回时允许复用仍属于本人且未删除的私有文件引用；审核中仍可正常发布和参团。
- 起终点使用原生双列滚轮，所有映射从唯一 8 条路线配置派生，提交只发送 `routeId`。

## 步骤

1. 增加失败测试：身份意向不授权、司机申请状态/脱敏、生产审核关闭、普通/待审司机不可承接、路线双向映射与滚轮列联动。
2. 增加后端常量、校验、错误映射、公开 DTO；扩展 Memory/Cloud Store 端口。
3. 增加 `onboarding.selectRole`、司机申请 submit/get/withdraw 与仅开发环境审核 action；保持 `ride.driver.accept` 只信任批准后的 driver/vehicle 事实源。
4. 扩展客户端 user/activity service 与 Mock Server，同步实现演示状态机且不出现完整证件号或 fileID。
5. 将资料页改为首次身份分流；增加司机认证分步页和“我的”状态入口。
6. 把发布拼车路线选择改为原生 `multiSelector` 双列滚轮，完成 routeId 与索引双向映射。
7. 运行专项测试、全量 `npm run verify`、语法与 diff 检查。
8. 分别交由 GPT-5.5 与网页版 Gemini 3.7 Flash 复审；修复 Critical/Warning 后真机验收。

## 暂不伪装完成的上线门禁

- 澳门个人资料处理告知、跨境传输、保存期限和人工审核制度须由运营/法律负责人确认。
- 生产加密/HMAC 密钥、私有云存储权限和审核员后台未配置前，司机申请只能处于待审核状态，不得生产自动通过。
