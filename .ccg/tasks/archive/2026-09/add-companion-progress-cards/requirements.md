# 拼同行活动进程 IP 卡片需求

## 目标

- 在既有 `leju-progress-card` 公共弹层中接入“拼同行”IP 卡片。
- 所有卡片沿用当前已经确认的排版、关闭按钮、主按钮与“稍后再看”布局，不改变图片的界面显示尺寸。
- 自动展示只允许由后端权威活动状态推导，禁止把交通工具、夜间行程或行前整装等未记录事实呈现为真实进度。

## 素材盘点

- `报名成功 / #出发准备官`
- `组队成功 / #同行默契搭`
- `行前整装 / #行李清单控`
- `高铁同行 / #旅途气氛组`
- `夜行途中 / #夜行陪伴官`
- 来源目录含一张“报名成功”的完全重复文件，接入时只保留一份。

## 权威状态映射

| 活动状态 | 拼同行卡片 | 自动展示 |
| --- | --- | --- |
| `RECRUITING` | `COMPANION_REGISTERED` | 是 |
| `FORMED` | `COMPANION_TEAM_READY` | 是 |
| `IN_PROGRESS` | 无 | 否 |
| `COMPLETED` | 无（缺少完成旅程素材） | 否 |

以下卡片仅注册为 `autoEligible: false`，供内部 debug / 后续权威事件接入：

- `COMPANION_TRIP_READY`
- `COMPANION_RAIL_TOGETHER`
- `COMPANION_NIGHT_JOURNEY`

## 安全边界

- `PUBLIC_TRANSIT` 不等于高铁，不能据此触发“高铁同行”。
- 当前没有夜间列车、出发时段或交通班次字段，不能触发“夜行途中”。
- 当前没有行李清单确认或整装完成事件，不能触发“行前整装”。
- `food` 与 `companion` 的普通解析、debug 解析必须严格按 `activityType` 隔离。
- 现有 owner/member/ACTIVE membership 的观看资格和本地最高已读水位机制保持不变。

## 资源与包体

- 活动分包当前约 1.31 MiB，预警线为 1.35 MiB，上限为 1.50 MiB。
- 六个餐饮素材与五个唯一同行素材需要统一做高质量 Baseline JPEG 优化；界面渲染尺寸保持不变。
- 优化后必须通过 `tests/package-size-budget.test.js`，并进行插画文字、纸纹、边缘与暗部的视觉抽查。

## 验收

- 拼同行 `RECRUITING`、`FORMED` 对合格成员分别显示正确卡片。
- 拼同行 `IN_PROGRESS`、`COMPLETED` 不自动弹出不匹配卡片。
- 三张非权威阶段卡仅能在 debug 开关开启且类型匹配时预览。
- 拼好饭现有映射、弹层排版、静音和已读逻辑无回归。
- 图片界面显示比例与大小不变；320×568 和系统大字下操作区无裁切。
- 全量测试、项目检查和包体门禁全部通过。
