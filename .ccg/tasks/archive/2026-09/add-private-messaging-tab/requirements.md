# 需求说明

## 目标

- 将 TabBar 从四栏调整为五栏：发现 / 社区 / 发布 / 消息 / 我的。
- “发布”固定为第 3 项，即五栏视觉中心。
- “消息”位于“发布”与“我的”之间。
- 中央“发布”使用越界凸起的手绘拼图形按钮，成为全局唯一主操作。
- 新增与现有深蓝粗纹纸、奶油白纸片、油画棒笔触一致的消息中心。
- 私信必须是真实可用能力，不能只增加空壳 Tab。

## 初步范围

- 主包新增消息会话列表 Tab 页面。
- 分包新增单聊详情页。
- 将原生 TabBar 切换为微信官方 `custom-tab-bar`，统一维护五项选中态、Safe Area 和消息未读 Badge。
- 服务端新增会话、消息、未读计数和已读状态接口。
- 仅登录、资料完整且已确认成年用户可发送私信；游客不可访问私信内容。
- 仅允许通过明确业务入口建立会话，禁止任意枚举用户或读取他人会话。
- 文本内容经过内容安全与联系方式/外链边界校验。
- 会话列表覆盖 loading / empty / error / pagination；聊天页覆盖发送中、失败重试、历史加载与业务失效。

## 暂定产品边界

- 首期只做一对一纯文字私信，不支持图片、文件、语音、群聊、转账或位置。
- 中央按钮允许越过 TabBar 顶边，但点击热区必须完整包含于自定义组件，并为页面正文预留相应底部避让。
- 拼图按钮使用统一母版的透明 PNG-32 激活/未激活资产；其余四项保持轻量线性手绘图标。
- 未读数优先使用原生 TabBar badge；没有未读时移除 badge。

> 修订：使用 `custom-tab-bar` 后未读 Badge 由自定义组件渲染并以真实未读接口驱动，不再调用原生 TabBar badge API。

## 待分析

- 屏蔽、举报、撤回、删除会话的首期边界。
- 消息保留周期与敏感信息策略。
- 现有 Mock/Cloud 双模式需要扩展的最小契约。
