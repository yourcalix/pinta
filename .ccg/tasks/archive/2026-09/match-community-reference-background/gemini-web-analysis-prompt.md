# Web Gemini 3.7 Flash 前端分析提示词

```text
ROLE: frontend UI/UX analyzer

PROJECT:
“拼吧”微信原生小程序，社区 Tab 面向用户讨论、提问与互助。品牌主色为 #16A36A，但本轮产品负责人明确要求社区页按所附论坛参考图一比一还原，包括参考图的粉白蓝柔焦背景；这一明确要求覆盖此前社区页使用深蓝纸纹的视觉约定。

REVIEW TARGET:
请同时查看用户上传的两张图片：
1. 参考图：顶部暖白、右上柔粉、中部粉蓝、底部浅蓝的柔焦论坛首页截图；
2. 当前实现截图：深蓝纸纹背景的“拼吧社区”页面。

当前页面代码结构：
- 动态 contentTopInset 下方居中“拼吧社区”标题；
- 100rpx 通栏社区规范；
- 两张 112rpx 快捷卡“发起讨论 / 社区守则”；
- “最新讨论 / 按发布时间”；
- 220rpx 起的白色帖子卡，展示昵称首字头像、时间、三行正文、真实点赞数和回复数；
- 页面底部使用自定义五栏 TabBar。

KNOWN CONSTRAINTS:
- 微信原生小程序 WXML/WXSS/JS，不引入 UI 框架。
- 375px 基准宽度，兼容 320px 窄屏、状态栏、右上角微信胶囊、底部 Safe Area 和凸起的中央发布按钮。
- 社区 DTO 仅有作者昵称、纯文本正文、发布时间、点赞数、回复数；没有图片、热门话题、置顶、浏览量、标签、分区或“新回/我发/我回/我赞”等数据。
- 不得伪造参考图里的帖子图片、浏览量、置顶、热门榜和无数据源 Tab。
- 需保留发帖登录/资料门禁、帖子详情跳转、游标分页、加载/空/错误状态。
- 背景将生成一张本地主包 Baseline JPEG：只包含柔焦粉白蓝抽象氛围，不含文字、人物、品牌、水印或 UI 元素。
- 图片格式需兼容 iOS 微信，禁止 WebP。

REVIEW QUESTIONS:
1. 请以 1125×2436 参考图为基准，逐区测算顶部标题、公告条、快捷卡、栏目栏、首张帖子卡的像素比例，并换算为 750rpx 设计稿参数。
2. 当前结构中哪些尺寸、边距、圆角、字体、颜色和阴影必须改动，才能更接近一比一还原？
3. 如何设置粉白蓝背景的色域、光斑位置、过渡范围及 background-size/background-position，确保长列表滚动时与参考图一致且不出现接缝？
4. 参考图有五个栏目 Tab，但业务仅有“最新讨论”。在不伪造功能的前提下，栏目区域应如何在几何上保持参考图的高度与视觉重心？
5. 白色帖子卡在无图片 DTO 时，应如何调整最小高度、内边距、正文行数和互动区，最大限度贴近参考图而不生成假图片？
6. 请检查 320px、大字体、内容很短/很长、空列表和分页加载时的布局风险。

OUTPUT:
1. 总体判断与最主要问题
2. Critical / Warning / Info 分级问题清单
3. 参考图像素测算表：区域、原图 px、换算 rpx、建议 CSS
4. 背景素材生成规范：尺寸/比例、构图、颜色、光斑位置、安全区、禁止元素、JPEG 导出要求
5. WXML/WXSS 修改清单，明确到选择器和 rpx 参数
6. 375px 与 320px 的完整垂直空间预算
7. 必须保留与不得伪造的业务边界
8. 实施后的验收清单

Do not assume missing business facts. Separate objective usability issues from subjective visual preferences. Do not write backend code.
```
