# 实施计划

## 综合结论

采用一个暖米白双 Tab 页面承载“关注 / 粉丝”。列表只允许本人读取，关系成员 DTO 不输出内部身份；每个成员由独立 `socialProfileNa_` 短期票据进入既有只读公开主页。前端只把安全数组索引放入 WXML dataset，真实票据保存在页面实例私有 Map，并通过现有一次性内存桥导航。

## 实施顺序

1. **共享契约与凭据**
   - 新增关系列表类型、游标锚点比较和 memberKey 工具。
   - 扩展短期票据模块，支持 `socialProfileNa_` 主页票据和 `profileFollowPage_` 不透明分页票据。
   - 扩展输入校验，严格拒绝额外身份字段。

2. **Memory / Cloud 数据层**
   - 新增关注关系稳定分页查询、用户批量读取、双向关系批量状态查询。
   - Cloud 使用 `updatedAt desc + _id desc`，游标通过两段条件查询保持同时间戳稳定性。
   - 保持关注写事务继续使用确定性文档 ID，不在事务内新增 `where`。

3. **服务层与 Mock**
   - 新增只读 `profile.follow.list`。
   - 过滤停用/无公开资料账号，生成最小公开 DTO、权威 summary、社交主页票据和不透明下一页票据。
   - 扩展公开主页票据解析和 Mock 同构实现。

4. **前端页面**
   - 主页关注/粉丝统计升级为保持原几何的可点击按钮。
   - 新增 `subpackages/profile/follows` 双 Tab 页面，覆盖骨架、内容、空态、首屏错误、静默刷新和分页状态。
   - 页面私有保存 profileNavToken；点击时执行 5 秒过期安全垫、一次性内存桥接和导航失败回收。
   - 公开主页把 `social` 来源归入暖米白主题，仍复用原关注/取关状态机。

5. **测试与文档**
   - 新增服务契约、隐私、分页、票据、Mock、页面状态与 320px 静态测试。
   - 更新 README 的两个 CloudBase 复合索引要求。
   - 更新前后端 spec，替换原“一期不提供关系列表”的旧约束。
   - 执行专项测试、`npm run verify`、`git diff --check`，再进入 GPT 5.5 与 Gemini 最终复审。

## 明确边界

- 不实现私信、拉黑、移除粉丝或列表内关注按钮。
- 不显示逐人在线状态。
- 不把 `profileNavToken`、内部用户 ID 或关系文档 ID写入 WXML、URL、Storage 或日志。
