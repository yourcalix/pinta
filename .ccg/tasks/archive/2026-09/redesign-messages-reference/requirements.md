# 按参考图重构消息主页

## 用户目标

- 将 `miniprogram/pages/messages/index` 按参考图一比一还原为暖米白消息中心。
- 保持现有五栏自定义 TabBar 及消息入口不变。
- 参考图只定义视觉和信息层级，不导入示例人物、示例图片、示例消息或虚假未读数。

## 真实能力映射

- “讨论动态”：进入现有 `subpackages/community/activity/index`，展示真实帖子回复、帖子获赞与评论获赞。
- “活动通知”：消费现有 `notification.list` 的真实申请、成团、活动状态通知，并通过受控 `notification-router` 跳转。
- “系统通知”：当前后端没有独立系统公告数据源，不得伪造。实现时需使用明确空态/说明，或在现有通知类型可可靠分类的前提下展示真实内容。
- 下方消息流：保留既有真实一对一私信及分页、未读与来源活动，不得因为视觉重构删除私信能力。

## 视觉目标

- 页面背景 `#F9F7F2`，居中“消息”标题，去除英文眉题和副标题。
- 顶部三张白色大圆角入口卡，左侧 3D 图标，中间标题与副标题，右侧细灰箭头；首项显示真实讨论动态未读提示。
- 下方私信卡按参考图做大圆角白卡、真实头像、昵称、时间、未读红点、消息摘要和浅米色来源活动摘要。
- loading / empty / error / 分页状态与 320px 窄屏、Safe Area、无障碍继续完整支持。
- 卡片触控反馈克制，不改变整页布局。

## 资产结论

- 现有金黄 3D 铃铛 `community-notification-bell.png` 可复用。
- 现有气泡为奶油色并带铅笔，现有帐篷为绿色森林场景，均无法一比一匹配参考图；需要两张新的透明 PNG：珊瑚橙三点气泡、暖黄橙帐篷红旗。

## 不变约束

- 打开消息 Tab 不直接清空未读；仅具体会话或通知成功消费后更新。
- 未读刷新失败保留最后确认值，不以 0 代替未知。
- 页面不直接调用云函数，继续通过 `services/`。
- 不增加伪造缩略图、帖子图片、在线状态、已读回执或虚拟系统助手。
