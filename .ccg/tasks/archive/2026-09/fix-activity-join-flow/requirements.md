# 修复已发布活动无法加入拼团

## 目标

- 保持非拼车活动“提交申请 → 发起人审核 → 审核通过后入团”的既有契约。
- 修复详情页在游客快照下显示“加入成团”，登录后未刷新真实身份而错误打开申请抽屉的问题。
- 登录后用权威详情快照收敛发起人、待审核申请人、已入团成员及普通访客的操作状态。
- 对不能申请的真实原因给出清晰反馈，不把业务限制表现为笼统“操作失败”。

## 已验证事实

- Mock 双账号端到端链路可正常完成申请、审批与成团。
- 发起人不能申请自己发布的活动是正确的服务端约束。
- 当前 `handleApplyOpen` 登录后不重新请求 `activity.detail`，可能继续使用登录前的 `guest` 快照。

## 范围

- `miniprogram/subpackages/activity/detail/index.js`
- `tests/activity-detail-design.test.js`
- 如测试需要，可补充既有拼团回归测试，但不改变后端入团契约。

## 验收

- 普通访客登录后仍可打开申请抽屉并成功提交待审核申请。
- 发起人登录后不打开申请抽屉，页面原子切换为“管理成员”。
- 已申请用户显示“申请审核中”；已入团用户显示成员空间入口。
- 双击、页面隐藏/卸载和晚到详情响应不会误开抽屉或写入离屏状态。
- 全量测试与工程检查通过。
