## 用户明确要求

1. “附近拼吧 · 正在发生”下面首批只展示 3 个真实活动。
2. 3 个活动必须像参考图底部“附近的人 · 正在发生”一样，横向一排三列，不是当前的纵向大卡。
3. 严格参考图片尺寸比例、头像/时间/标题/封面位置、圆角、留白、阴影和字体层级。
4. 其余活动通过右侧“查看更多”呈现；首页现有后端接口是每次用不透明 cursor 请求 3 条，当前实现会向现有数组继续追加 3 条。
5. 活动卡只能消费真实公开 DTO：活动标题、类型、状态、时间、地点、发起人昵称与公开头像、真实成员头像、真实名额。不得伪造参考图里的照片、发布时间、浏览量、点赞、报名人数或帖子文案。
6. 当前 Hero 主插画继续留空，另两张素材尚未提供，禁止临时错配。

## 当前页面与工程条件

- 页面内容宽度：375px 设备为 694rpx（左右各 28rpx）；320px 设备为 600rpx（左右各 20rpx）。
- 背景：#F9F7F2 暖米白。
- 章节标题：“附近拼吧 · 正在发生”，右侧为“查看更多 ›”，按钮有效热区至少 88rpx 高。
- 当前活动卡是 46:54 左右分栏、min-height 390rpx 的纵向列表卡；这个结构不适合三列。预计新增仅首页使用的 compact-grid/home-preview 变体，不能破坏其他页面现有活动卡。
- 现有首页首次 limit=3；点击查看更多通过 cursor 再取 3 条并合并去重；请求期间保留已有内容。
- 卡片必须整卡唯一点击跳转热区，读屏标签继续包含类型、标题、状态、时间、地点与名额。
- 320px 窄屏也要保持三列，不退化为单列、不产生横向滚动。
- 系统大字模式必须有安全策略，不能让三列互相覆盖。

## 重点分析问题

1. 精确测算三列卡片：694rpx / 600rpx 两种内容宽度下，列宽、列间距、卡片高宽比、封面图比例与高度。
2. 在每张约 210–220rpx 宽的窄卡内，真实活动字段应如何取舍和排序，既接近参考图又不挤压：发起人头像/昵称、相对或格式化时间、2 行标题、封面/主题插画、状态或名额应分别放在哪里？地点是否应在首页三列预览中隐藏但保留在 aria-label？
3. 参考图存在“有图、无图、短文本”三种卡片节奏。我们的活动类型封面是本地透明 PNG（拼同行/拼运动/拼饭桌），应统一固定封面区域还是允许无图卡？请基于视觉一致性和真实数据约束给结论。
4. “查看更多”的最佳实现：
   - 当前 cursor 每次取 3 条并追加；
   - 是否应保持三列网格并每次追加一整行 3 张；
   - 加载后按钮放在所有行下方还是仍放章节标题右侧；
   - 如何避免用户点击后误以为跳页、以及避免视口跳动。
5. 给出骨架屏、加载失败、末页文案的对应三列布局参数。
6. 给出系统大字模式的可交付降级策略；若坚持三列会损害可读性，请提供在不违背用户“参考图三列”常规模式要求下的辅助模式方案。
7. 审查这 10 张素材的槽位映射是否正确；指出顶部图标、快捷卡 3D 图、TabBar 图标和白色加号的具体显示尺寸、内边距与 opacity。
