# 实施计划

## 目标

在已完成的“深蓝品牌头部 + 白色连续内容面板”发现页基础上，加入站内运营 Banner 和真实“成团记忆”，并保证两路内容彼此解耦、无伪造数据、无死链。

## 设计与产品决策

1. 页面顺序固定为：品牌头部 → 运营 Banner → 搜索 → 类型筛选 → 正在组队 → 成团记忆 → TabBar/Safe Area 避让。
2. Banner 使用项目内既有 PNG 插画与 CSS 渐变组成三张受控运营卡；原生 `swiper` 自动轮播，单张时停止轮播，点击只接受本地白名单目标。
3. 成团记忆仅消费新的只读 `activity.memories` 接口中服务端强制筛选的 `FORMED` 活动；不接受客户端状态参数，不展示点赞、评分、用户现场照片或其他虚构事实。
4. 首屏固定显示最多三条：1 条通栏、2 条双列、3 条 1 大 + 2 小；接口最多返回 6 条，按钮在本页展开其余真实记录，避免创建需求不完整的二级页。
5. 记忆请求失败或结果为空时整块隐藏；不污染正在组队的 loading/error/pagination 状态。页面隐藏或卸载后，两个请求序列分别失效。

## 实施顺序

1. 新增后端/API、Mock、页面状态与视觉结构的失败测试。
2. 在校验层增加严格的成团记忆只读入参；在 MemoryStore 与 CloudStore 增加按 `formedAt / updatedAt / startsAt` 倒序的受限读取。
3. 在领域服务与 Mock Server 暴露公开 `activity.memories`，复用现有公开活动 DTO 与头像水合逻辑。
4. 在前端 service 增加 `memories()`；发现页并行、独立加载活动列表和成团记忆，加入过期响应保护。
5. 在发现页加入 Banner、指示点、拼贴卡、真实事实文案、展开/收起与详情跳转。
6. 完成 320px 样式、图片错误降级、按钮热区和无障碍语义。
7. 运行定向测试、全量 `npm run verify`、微信开发者工具预览编译。
8. 按 CCG 路由执行 GPT-5.5 后端审查与网页版 Gemini 3.7 Flash 前端审查，修复 Critical/Warning 后归档、提交并普通推送。

## 验收标准

- 客户端无法让记忆接口返回非 `FORMED` 活动。
- 记忆 DTO 不新增隐私字段；卡片只展示活动公开 DTO 已有事实。
- 主列表失败不影响记忆；记忆失败不影响主列表；离屏晚到响应不更新页面。
- Banner 具备 16:7 比例、手势/自动轮播、自定义指示点、图片失败隔离与路由白名单。
- 1/2/3/4–6 条记忆均有稳定布局，320px 无横向溢出。
- 无 WebP、新 UGC 上传、第三方品牌或参考图素材。
