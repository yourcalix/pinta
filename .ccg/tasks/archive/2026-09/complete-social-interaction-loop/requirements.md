# 初始需求

完善用户侧社交互动功能，覆盖私信、社区帖子发布、评论、点赞及相关入口、列表状态、未读/失败/重试/权限与数据一致性，形成从发现内容、参与讨论到一对一沟通的闭环。

## 边界

- 继续面向所有成年人，沿用登录、基础资料完整、年满18岁与账号可用门禁，不恢复学生认证。
- 沿用当前亮蓝拼图纸纹、奶油白纸片和手绘交互体系；不引入UGC图片、粉丝、关注、在线状态、已读回执或复杂推荐系统。
- 服务端为事实来源；Mock 与 Cloud 契约保持一致；写操作具备幂等、防重复提交和权限校验。
- 私信保持现有共同活动成员关系约束与纯文字500字限制；本轮先审计并补齐缺口，不破坏已完成的轮询/草稿/重试/已读机制。
- 社区需要帖子列表、发布、详情、评论、点赞/取消点赞、删除权限、分页和状态闭环；具体产品细节以现有代码和前端评审综合为准。
- 点赞覆盖帖子和一层评论；不增加楼中楼。社区列表默认只展示点赞/评论计数，实际点赞在详情完成，以避免整卡导航和嵌套按钮热区冲突。
- 详情消费现有评论游标，支持加载更多、ID去重、刷新抢占、局部失败重试；新评论成功后以服务端DTO合并，不让客户端计数成为最终事实。
- 不在分析阶段部署云函数或写入真实云数据；真机与真实云联调继续留到后期统一执行。
