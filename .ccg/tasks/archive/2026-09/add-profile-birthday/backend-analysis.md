# GPT-5.5 后端分析摘要

## 推荐契约

- 新增可选自有资料字段 `birthDate: YYYY-MM-DD`，历史用户缺失时 self DTO 返回 `null`。
- 生日是日历日期，存字符串而非时间戳，禁止使用 `Date.parse` 作为合法性判断。
- 服务端按纯年月日验证格式、闰年、月日范围、未来日期和 `1900-01-01` 下限。
- 业务当前日期固定按澳门/UTC+8 日历日计算；传入生日时必须年满 18 岁，同时继续要求 `adultConfirmed === true`。
- 完整生日仅允许 authenticated self profile DTO 返回，不进入活动、社区、群聊、私信、成员或分享 DTO，也不写审计详情。
- 不存年龄或星座等派生字段。

## 兼容策略

- 本阶段生日非必填，不阻断历史用户与旧客户端。
- 历史 profile 无生日时正常读取为 `null`。
- 资料更新采用“未传生日则保留旧值”的服务端合并语义，避免旧客户端整体更新时抹掉生日；显式清除是否允许需由产品约束决定。
- Mock 与 Cloud 的验证和 self DTO 白名单必须一致。

## 不纳入范围

- 参考图中的“显示星座”暂不加入。它会新增公开展示偏好、派生字段和隐私策略，应作为独立需求且默认关闭。

## 关键测试

- 合法闰年、非法闰年、非法月份/日期/格式、未来日期、过老日期。
- 刚满 18 岁允许、差一天满 18 岁拒绝。
- 历史用户读取兼容、旧客户端更新不抹生日。
- self DTO 可见生日，所有公开 DTO 不泄漏。
- Mock 与正式服务契约一致。
