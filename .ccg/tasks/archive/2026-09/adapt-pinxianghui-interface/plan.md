# 拼享惠界面与真实发布闭环适配计划

## 约束结论

- 附件作为视觉与字段意图参考，不直接覆盖生产文件。
- 拼享惠作为独立 `benefit` 活动类型接入，不复用 `food` 数据结构。
- 不采纳手机号、微信号等公开联系方式字段；成团后继续使用现有成员空间与群聊。
- 保留现有幂等发布、成人资料门禁、草稿、7 天时间窗、2—20 人、内容安全、键盘和安全区逻辑。
- 线上优惠不强制地图地点；线下门店地点可选。
- 原始素材先压缩并仅放入发布分包，主包只复用现有 `publish-cover-benefit.png`。

## 实施顺序

1. 新增后端 `benefit` 白名单、优惠类型枚举、字段校验、公开 DTO 清洗和内容安全扫描。
2. 新增前端显示元数据，使发现、活动列表、附近筛选、详情、消息来源和卡片封面识别 `benefit`。
3. 将发布入口的拼享惠从筹备态改为真实可用，并纳入草稿恢复。
4. 在共享发布表单中新增完全隔离的拼享惠分支，使用安全字段：商家/平台、优惠类型、优惠门槛、目标价格、预计节省、优惠说明、使用规则、计划时间与人数；不显示联系方式。
5. 适配并压缩用户提供的手绘素材，保持橙色纸张与票券视觉，同时保证 320px、键盘和安全区布局。
6. 同步 mock 和测试：校验、创建、详情、列表、草稿、筛选、封面、内容安全和包体预算。
7. 跑专项测试与全量 `npm run verify`，再进行 GPT-5.5 后端审查和网页版 Gemini 前端审查。
