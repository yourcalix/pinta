# 需求

用户真正阅读一条讨论动态对应的帖子后，返回“讨论动态”时，该动态卡片的未读红点应消失，“全部 / 回复我的 / 收到的赞”中的对应未读数应减少；继续返回发现页时，右上角讨论铃铛数字也应同步减少。

## 代码事实与范围

- `pages/publish` 当前没有铃铛；讨论未读铃铛实际位于 `pages/community/index`（发现页）。本任务按既有产品上下文同步该铃铛，不向发布 Tab 新增入口。
- 详情页仅在首屏成功或目标回复成功定位后调用 `community.activity.read`，导航失败、详情失败或定位网络失败不得清除未读。
- 动态列表、分类汇总和发现页铃铛都必须以服务端权威 `read` 与 unread summary 为最终事实。

## 状态约束

- 已读写请求在途时，返回页面的动态列表与未读汇总读取必须等待其结算，避免先读到旧快照后再也不刷新。
- 只有 `read === true && stale !== true` 可作为当前版本成功已读的证据。
- `stale === true` 表示动态已产生新版本，不能清当前卡红点或扣数字，应重新读取权威列表与汇总。
- 网络失败、超时或页面未真正展示成功时保留原未读状态。
- 页面已有 `_loadSeq`、`_unreadSeq` 与生命周期守卫必须继续生效，旧响应不得覆盖新状态。
- 不使用固定延时二次刷新，不新增跨页面持久化未读缓存，不修改后端契约。
