# 参考活动详情 + 真实群聊 + 发起人咨询实施计划

阶段：planning。复杂度 L / 风险 high。已取得 GPT-5.5 后端分析和用户贴回 Web Gemini 前端分析。主会话逐文件实施，不委派子代理。

## 已明确的权限选择

用户确认不允许读取加入前历史：新加入及重新加入只看本次加入之后的群消息。以加入事务记录的群消息序号作为可见下界；本次成员周期重新生成，不复用前次已读状态和可见边界。所有列表、摘要、未读和幂等返回共享该过滤规则，不能使用客户端时间或仅按同毫秒时间戳判断。旧成员缺少可信边界时不能默认放开所有历史。

其余保守边界：原 MEMBER_DM 契约不变；新咨询及群聊下架禁读写、终态只读、不新建终态空咨询。群聊只有当前 ACTIVE 成员可读写；退出后不得继续拉历史。未读第一版只做可靠的新消息提示，不虚构精确群计数。

## 1. 契约与测试骨架

- 在 backend spec 中区分新增 OWNER_CONSULT 与原 MEMBER_DM；旧无 kind 的会话按 MEMBER_DM 处理。
- 新增群聊/咨询契约测试，覆盖账号、资料、活动状态、动态成员权限、历史可见范围、自己咨询自己、下架、幂等冲突、并发失权、游标稳定及条件已读。
- 核验当前成员创建/重入事实，在同一加入事务读取群序号并记录成员周期及可见下界。新增同毫秒前后消息、加入与发送并发、退出后重入、旧游标/旧幂等ID重放、旧已读状态、历史摘要泄漏测试。禁止客户端提供权限时间或咨询目标用户 ID。

## 2. 后端基础与存储

- 新增纯函数聊天策略和校验，复用正文安全与复合游标机制。
- Memory Store 实现咨询创建、按类型可写性、群消息/读状态/摘要；账号与动态权限在幂等返回前校验。
- Cloud Store 对应实现：事务仅 doc(id)，事务内重验权限，消息和摘要同一事务；为查询增加实际索引说明，不部署。
- 群消息 ID 由活动/服务端身份/clientMessageId确定性生成；相同ID不同payload拒绝；审核和限流不因重试重复累计。

## 3. 服务 API 和 Mock

- service 增加 dm.consult.create、群聊list/send/read及群会话列表/未读入口；输出白名单DTO，不暴露内部身份与申请备注。
- 私信旧接口不放宽，按会话种类精确判断权限。
- Mock同契约与生命周期，不以模拟成功替代Cloud实现。
- 同步services适配层，页面不直调云函数。

## 4. 消息页面与详情入口

- 新增分包真实群聊页面及路由，复用现有纯文字消息的串行轮询、失败幂等重试、游标追赶、离屏响应隔离与键盘安全模式。
- 私信页支持咨询来源和终态只读，不暴露活动其他成员信息。
- 本轮按参考详情的明确范围，以详情底栏作为成员群聊入口；不额外扩张消息主页的信息架构。群会话聚合列表与 TabBar 群未读汇总留待独立任务，现有私信和通知分区保持不变。

## 5. 活动详情视觉和按钮

- 仅修改活动详情，不影响发现列表、其他Tab或旧ride专用流程。
- 按参考面板起点约屏高75%计算高幅封面；在相同视口进行截图对照，不使用700rpx估算代替参考。图片内容不足时明确示意资产限制。
- 纯白面板、浅灰信息区、细分割线及独立圆头像；保留真实空槽回退、稳定key和完整人数信息。
- 导航透明/白底离散切换，不仿制微信胶囊。
- 群聊跳真实群聊页；聊下按活动创建发起人咨询；分享原生；加入成团保留现有非拼车审批并明确等待确认。
- 黑色亮绿主按钮按角色状态显示合理操作；所有热区至少44px，保持窄屏弹性宽度和Safe Area。

## 6. 验证与审查

- 逐文件语法检查与相关测试，最终全量Node测试、结构校验和git diff范围核对。
- Memory/Cloud harness/Mock行为一致；退出/下架期间请求、重复发送、条件已读和分页边界重点回归。
- 模拟器相同视口首屏/中段/底部截图与参考对照；320px与长标题验证；无原海报素材不宣称逐像素一致。
- 后端真实GPT-5.5复审，不以其他模型或本地fallback代替；前端输出完整代码/截图审查材料交用户粘贴Web Gemini并等待真实结果。
- 真机键盘、冷启动、双账号群聊/咨询联调需真实环境证据，未执行则明确待验。
