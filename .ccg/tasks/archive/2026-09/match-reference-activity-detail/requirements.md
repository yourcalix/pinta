# 最新用户目标：匹配参考，而非品牌化改编

用户明确要求图片显示比例、按键和详情页与三张参考截图一致。此前420rpx紧凑封面、奶油白、手绘虚线、翡翠绿实心CTA不再作为此详情页的设计约束。发现页和其他页面不在本次修改范围。

## 已明确的视觉方向

- 首屏全宽高幅海报，上覆导航；不为了露出更多信息压缩封面。参考展示图946px宽，内容面板约从1536px高度开始，约占屏幕高度75%，仅是截图测量，不将屏幕位置误认为海报原始宽高比。
- 纯白连续内容面板，上缘大圆角；黑色粗标题，浅灰信息区，细灰分隔线。
- 头像为独立间距的一排圆形，而非当前重叠小头像。
- 固定白色底栏：参考为左侧三个图标入口、右侧黑色长胶囊配亮绿色文字。
- 滚动后导航由海报上的半透明样式变为白底深色内容；系统状态栏与微信胶囊由微信提供，不仿制。
- 不得宣称逐像素一致，直到使用相同视口实测并对照；不同内容长度、缺少原始海报/图标素材会影响最终匹配。

## 用户已确认的按钮业务

- 群聊：当前活动已加入成员的群聊，不是微信群导流，也不是成员空间的改名。
- 聊下：与活动发起成员一对一私信。
- 上车支付替换为加入成团，无支付。
- 分享保持微信原生分享，三枚次级入口+黑底亮绿主CTA的参考布局不变。

## 已确认的群历史隐私规则（2026-09-04）

用户回复“不允许”：新加入和退出后重新加入的成员，都只能读取本次加入后的群消息。重新加入不能恢复上一段成员期间的历史读取权限。

- 该边界须在服务端执行，覆盖群消息分页、消息中心摘要/预览、未读提示、消息ID读取、重试返回和已读操作，不能只在页面隐藏。
- 成员退出立即失去群读写权限，重新加入建立新的可见起点；客户端隐藏/离开群聊页面清除敏感会话数据，重新显示时重新鉴权，丢弃旧成员周期的在途响应。
- 同毫秒加入/发送的先后由服务端持久化顺序界定，不能单靠 createdAt >= joinedAt 放行；加入事务记录群消息序号边界，之后仅返回更大序号。
- 历史成员缺少可信边界时不得默认从0读取所有历史；需使用可证实的初始化规则或fail-closed。

## 其他暂定实现边界（已向用户说明）

- 群聊只对ACTIVE成员（含发起人）开放；审批中申请人不算已加入。招募中已加入成员可聊天。退出成员不能再读写；终态仍ACTIVE成员只读，具体生命周期由后端分析核验。
- 咨询发起人允许未加入但已登录、资料完整用户使用；不能向自己发私信；不得把旧共同成团成员私信契约整体放宽。
- 加入成团暂保留现有审批：申请成功进入待审核，获批后才加入；不默认改成直接占位。无新增支付和退款。
- 当前源码没有群聊API/页面。现有dm.conversation.create要求activityId+memberId且共同成团成员，只能复用部分消息能力，需新增咨询权限路径。
