# 乐聚拼吧活动进程 IP 卡片需求

## 目标

- 在活动详情页接入可复用的 `leju-progress-card`，以真实活动事实展示当前最新进程阶段。
- 首批覆盖用户提供的「拼好饭」六阶段素材；第二套素材需先确认业务语义后再接入，禁止把出行/高铁插画误配为攀岩阶段。
- 卡片只在详情、用户身份、活动状态均已确定后低优先级展示，并与申请抽屉、集合地点弹窗等高优先级交互互斥。
- 同一用户、活动、阶段支持本次会话抑制与短期稍后提醒；图片失败必须安全降级，不阻断详情主流程。

## 已核实的事实

- 服务端活动状态只有 `RECRUITING / FORMED / IN_PROGRESS / COMPLETED` 等通用状态，详情接口当前不返回 `serverNow`。
- 详情公开 DTO 提供 `type`、`typeData`、`viewerRole`、`viewerMembership.joinedAt`、`startsAt`、`status`、人数等字段；不存在菜单确认、装备确认、签到、路线完成等权威事件字段。
- 当前 `activity.detail` 仅返回 `{ activity }`，无法诚实推导 `GEAR_READY / MENU_READY / CHECKPOINT` 等阶段。
- 详情页已有申请抽屉与集合地点品牌弹窗；进程卡片必须服从它们，不得抢焦点或并发叠层。
- 活动专属大图必须位于活动分包；活动分包预算上限为 1.50MiB，不能直接放入约 24MiB 的原始 PNG。
- `拼好饭` 目录包含完整六阶段素材；`拼同行` 目录只有五张唯一的旅行/高铁主题素材，另有一张“报名成功”重复图，并非攀岩素材。

## 安全与诚实边界

- 不根据当前时间、人数或自由文本猜测不存在的业务事件。
- 只有服务端可验证的阶段才能自动展示；不可验证阶段需后端事件契约或明确的产品降级方案。
- 新代码、组件与用户文案使用「乐聚拼吧」命名；不在本任务中无边界全局替换旧品牌字符串。
- 本地记录不得存储服务端凭据或敏感身份字段；按现有匿名会话作用域或本地不可逆/非敏感范围设计。

## 验收重点

- 320px、iOS、Android、系统大字、图片失败、弱网与页面快速切换。
- 不与既有浮层冲突；页面隐藏/卸载后无晚到定时器或离屏 `setData`。
- 非目标活动和无权威阶段时不展示、不伪造。
- 新增素材经尺寸与包体校验，保持原比例，不裁切主体。
