# Web Gemini 3.7 Flash 前端分析

## 结论

- 评审结论：`APPROVE_PLAN`。
- 同意采用 Input Tips 一级检索与 `v3/place/text` 二级兜底的状态机。
- 一级有合法澳门坐标时必须立即返回，避免额外请求。
- 一级成功但候选为空，或原始候选全部缺少合法坐标时，才允许发起二级文本检索。
- 一级网络、非 2xx、鉴权或响应异常必须立即短路，不得继续放大为第二个同域请求。

## 状态与交互边界

- 两层原始候选都为空时才展示真实空态“没有找到地点，请换个关键词”。
- 任一层存在原始候选，但两层最终都无法形成合法澳门坐标时，保留 `AMAP_COORDINATES_UNAVAILABLE` 错误态。
- 二级请求失败沿用现有安全错误码；页面复用当前关键词的“重新加载”能力即可，无需新增视觉状态。
- 不输出高德 Key、上游 `info/infocode`、底层 `errMsg` 或用户位置。

## 兼容性关注

- Input Tips 的行政区字段为 `district`，POI 文本搜索常用 `adname`，清洗器需兼容两者。
- 二级结果继续复用澳门经纬度边界、名称和坐标校验。
- 页面现有 `_searchSeq` 与防抖逻辑继续负责丢弃过时结果，无需修改 WXML/WXSS。

## 必测场景

1. 一级有效时只请求一次。
2. 一级有无坐标候选时二级补齐。
3. 一级空数组时二级补齐。
4. 两层皆空与坐标不可用严格区分。
5. 一级网络失败不发二级请求。
6. `district/adname` 兼容与澳门边界过滤。
7. 所有错误信息保持脱敏。
