ROLE: frontend UI/UX analyzer and reviewer

PROJECT:
“拼吧”微信小程序，面向澳门年轻用户的活动拼伴与社区产品。用户希望把“社区”Tab 的排版按所附论坛首页参考图一比一还原，但仍须沿用拼吧品牌、真实数据契约与微信原生小程序约束。

REVIEW TARGET:
请用户同时上传本轮参考图（顶部居中论坛标题、通栏热门话题、双快捷卡、五栏导航、白色帖子卡的页面）。当前阶段是实施前版式分析，需要输出可直接转成 WXML/WXSS 的结构和 rpx 参数，不需要写代码。

当前社区页结构：
- 自定义导航，动态 `contentTopInset` 避让状态栏和微信胶囊。
- 深蓝纸纹背景。
- 左对齐三行 Header：`PINBA COMMUNITY / 拼吧 · 社区 / 聊兴趣，也分享互助经验`。
- 一条奶油白“发起讨论”入口。
- “最新讨论 / 当前已加载数量”标题。
- 纯文字帖子卡：56rpx 单字头像、昵称、相对时间、最多三行正文、真实点赞数、真实回复数、查看箭头。
- 游标触底加载及 loading / empty / error / load-more-error 状态。
- 底部使用项目已有五栏自定义 TabBar。

KNOWN CONSTRAINTS:
1. 参考图只作为排版和视觉层级依据；不得复制其中的 BISTU 名称、热门问题、诈骗公告、校园专属功能、用户头像或配图。
2. 当前公开帖子 DTO 仅包含：作者昵称、纯文字正文、创建/更新时间、真实点赞数、真实回复数、viewer 状态。
3. 没有帖子图片、话题标签、浏览量、置顶、用户榜单或“我发/我回/我赞”筛选接口；禁止伪造字段、假图片宫格或无效 Tab。
4. 列表页只展示点赞数和回复数；点赞与回复操作在帖子详情页完成。
5. 社区配图上传仍禁止。本轮只改社区首页 WXML/WXSS 与必要的纯展示装饰逻辑，不修改后端契约。
6. 顶部通栏建议映射为真实的社区安全/友善讨论提示，不伪装为用户热门帖。
7. 双快捷卡建议映射为“发起讨论”和“社区守则”；前者进入已有发帖页，后者只能展示真实只读规则。
8. 只能展示实际可用的“最新”栏目；如需要保持参考图横向节奏，请提出不会被误认为可点击功能的处理方式，禁止放 4 个不可用假 Tab。
9. 帖子无图片时必须自然收口，不保留参考图图片宫格的空白高度。
10. 保留现有游标触底加载、局部重试、空态、错误态与整卡详情跳转。
11. 自定义 TabBar 不改；页面底部须避让中央凸起发布按钮与 safe area。
12. 320px 窄屏不能横向溢出；交互热区至少 88rpx；正文最小 28rpx、辅助文字最小 24rpx。
13. 一级 Tab 顶部继续复用主包 `/assets/images/shared/shared-paper-bg.jpg` 和既有全局遮罩，不新增 WebP、外部图片或运行时模糊背景。
14. 作者继续使用受控单字色块头像，社区 DTO 不允许透传用户自定义头像。

希望接近参考图的区域：
- 安全区中的居中单行“拼吧社区”标题；
- 标题下约 100–112rpx 高的白色通栏提示卡，右上有低权重角标和右箭头；
- 两张等宽、约 100–112rpx 高的浅色快捷卡；

- 约 24rpx 圆角白色帖子卡，作者行、正文、真实点赞/回复信息高密度排列；
- 模块左右边距约 28–32rpx，卡间距约 18–20rpx。
