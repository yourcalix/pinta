# 主会话初步分析

## 参考图视觉骨架

1. 自定义导航安全区内居中单行标题，右侧保留微信胶囊空间。
2. 顶部大面积柔和氛围背景，正文模块直接叠在背景上，不增加独立深色 Hero。
3. 标题下依次为：通栏提示条、左右双快捷入口、等宽栏目导航、白色帖子流。
4. 帖子卡使用约 `24rpx` 圆角，作者行、正文和底部互动数据形成高密度信息流；卡间距明显小于顶部模块间距。
5. 自定义 TabBar 继续由项目全局组件提供，不仿制参考图底栏。

## 数据与产品边界

- 当前公开帖子 DTO 只有：`author.nickname`、`content`、`replyCount`、`likeCount`、`createdAt`、`updatedAt` 及本人/点赞状态。
- 不存在图片、话题、浏览量、置顶、校园功能卡、用户帖子分类查询等契约。
- 因此不复制参考图中的配图宫格、热门帖子文本、诈骗公告数字、浏览量、置顶徽标、“分配对象/联系墙墙”或不可用的“新回/我发/我回/我赞”标签。
- 顶部提示条使用平台真实社区规范文案；双入口映射到现有发帖能力和只读社区规则提示。
- 帖子仍保持整卡唯一导航热区；列表页只展示点赞数和回复数，不在列表执行点赞。

## 初步落地方案

- 保留统一纸纹背景和项目品牌色，改为参考图的居中标题与紧凑顶部模块层级。
- 将当前单一发帖条重构为：顶部社区提示通栏 + 双列快捷卡，其中“发起讨论”进入现有 compose，“社区守则”展示只读规则。
- 栏目导航只显示真实可用的“最新”，可辅以当前页真实数量，不渲染伪功能 Tab。
- 白色帖子卡采用参考图的头像/昵称/时间头部、3 行正文、底部真实点赞与回复数据；无图片时自然收口，不预留空白图片区。
- 延续现有游标触底加载、加载更多失败局部重试、loading/empty/error 状态。
- 320px 下双入口保持两列，文字单行省略，核心按钮热区至少 `88rpx`。

## Gemini 3.7 Flash 分析综合

- 采纳：居中单行“拼吧社区”、`100rpx` 社区提示通栏、`112rpx` 双快捷卡、单一“最新讨论”激活栏目、白色紧凑纯文字帖子卡。
- 采纳：正文 `30rpx`（窄屏 `28rpx`）、最多三行，长连续内容使用 `overflow-wrap: anywhere` 与 `word-break: break-word`。
- 采纳：点赞与回复数据右对齐，仅作为整卡详情语义的一部分，不增加列表内独立操作。
- 采纳：提示通栏和“社区守则”卡复用同一个只读原生 Modal；“发起讨论”沿用现有登录和资料完整性检查。
- 不采纳：浅绿/浅蓝 CSS 渐变。项目一级 Tab 规范禁止叠加额外渐变，改用低饱和纯色底。
- 不采纳：任何“新回 / 我发 / 我回 / 我赞”、图片宫格、置顶、浏览量、虚构话题或自定义社区头像。
