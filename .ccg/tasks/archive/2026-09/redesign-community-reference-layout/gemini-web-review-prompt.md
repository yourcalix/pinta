ROLE: frontend reviewer

请审查一个微信原生小程序“社区”Tab 的最终实现。目标是在不伪造业务字段的前提下，严格吸收参考图的版式：居中标题、通栏公告条、双快捷功能卡、讨论栏目、白色大圆角纯文字帖子流；视觉语言需与项目既有深蓝纸纹背景、翡翠绿强调色和自定义 TabBar 一致。

参考图特征：
- 顶部状态栏与微信胶囊下方为居中单行论坛标题；
- 一条白色大圆角热门/公告入口；
- 下方两张并排的浅色快捷卡；
- 再下方为栏目导航与白色帖子卡列表；

本项目真实数据边界：
- 社区公开列表 DTO 只有 author.nickname、author.avatarKind、content、replyCount、likeCount、createdAt、updatedAt 及 viewer 状态；
- 没有帖子图片、话题、浏览量、置顶、热门榜、分区或“新回/我发/我回/我赞”等数据；
- 因此实现不得伪造这些内容；社区列表继续用昵称首字和受控低饱和色盘，不公开自定义头像。

最终实现摘要：
1. 顶部：深蓝纸纹背景上使用 88rpx 高的居中“拼吧社区”标题，复用动态 contentTopInset 避让状态栏和微信胶囊。
2. 公告条：100rpx 高白色圆角“社区规范 / 友善交流，共建安全拼单社区”，整条点击打开只读 wx.showModal 守则。
3. 快捷卡：两张并排 112rpx 浅色卡——“发起讨论 / 分享问题与互助经验”和“社区守则 / 安全、隐私与友善表达”；图标全部用 CSS 绘制。
4. 栏目：只展示真实“最新讨论”和右侧“按发布时间”，不伪造多 Tab；绿色 48×6rpx 活跃下划线。
5. 帖子卡：白色 24rpx 圆角，min-height 220rpx；64rpx 单字头像、昵称、时间；正文 30rpx、最多三行、连续英文可断行；底部只展示真实点赞数和回复数并右对齐；整卡是唯一详情导航热区。
6. 状态：保留 loading/empty/error/load-more/retry/end；保留 onReachBottom 游标分页。底部为“已经到底啦 · 拼吧社区”。
7. 320px 适配：左右内边距 20rpx，公告 92rpx、快捷卡 104rpx、帖子 min-height 200rpx，文字和头像同步收紧；底部为自定义 TabBar 与 Safe Area 预留 calc(160rpx + env(safe-area-inset-bottom))。
8. 交互：发起讨论继续走现有登录与资料完整度校验；守则入口无新增假路由。
