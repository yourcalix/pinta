# GPT 5.5 业务与接口边界分析

## 结论

猫狗品牌弹窗必须作为页面内受控异步状态机接入，不能仅替换 `wx.showModal`。实现前必须守住以下硬约束：

1. 发布网络重试冻结首次校验后的 `payload` 与 `submissionKey`，重试只能复用同一快照，禁止同一幂等键对应不同内容。
2. 后端发布成功并删除草稿后，设置独立成功标记；成功弹窗停留、跳转、页面隐藏或卸载均不得让草稿复活。
3. 网络弹窗只处理超时、网络不可达、无响应等传输异常；业务校验错误、权限错误与已经全局处理的账号禁用错误继续走原错误链路。
4. 删除确认继续保持原动作锁，确认函数返回 Promise，并在确认、取消、遮罩关闭或页面卸载时可靠结算，避免重复删除或永久锁死。
5. 定位弹窗只能由用户主动点击定位入口后触发，复用现有 `wx.getSetting`、`wx.openSetting` 与 `locateAndLoad`，不得首屏索权或持久化坐标。
6. 所有异步回调继续受 `_disposed`、动作令牌及请求序号保护。

## 发布状态机

`idle -> submitting -> successModal | networkModal | businessError`

- 首次提交：校验并冻结 payload/key；订阅消息请求只执行一次。
- 网络重试：按钮 loading 防重，仅重放冻结的 `activity.create`。
- 成功：删除草稿、抑制后续草稿保存、展示成功弹窗。
- 点击“去看看”：单次跳转活动详情。

## 删除状态机

保留原 action sheet 与删除后的本地数据更新，只把二次确认 UI 替换为品牌弹窗。取消绝不调用 API；确认后 loading 防连击；页面隐藏或卸载结算待确认 Promise。

## 定位状态机

默认不索权。用户点击后检查设置；无权限显示品牌弹窗。确认后复用 openSetting，授权成功才定位；取消或仍拒绝时保留 denied/全城入口。隐藏或卸载继续清空临时坐标与使晚到请求失效。

## 必测边界

- 发布成功弹窗与草稿不复活。
- 传输失败重试复用同 payload/key，且不重复订阅授权。
- 业务错误不显示网络弹窗。
- 列表/详情删除取消不调用 API，确认只调用一次。
- 删除回复后 replyCount 与 replyTarget 正确校准。
- 定位首屏不索权、取消不调用定位、授权成功后正常加载。
- 页面卸载后无晚到 setData 或导航。

原始审查 Verdict 为 `REQUEST_CHANGES`，上述硬约束已纳入实施计划输入。
