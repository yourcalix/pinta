# 拼吧多场景校园拼单平台：第一版最终设计方案

## 1. 产品定位

拼吧从“校园拼车工具”升级为“校园学生拼单与搭子活动平台”。平台负责学生认证、活动发布、成员加入、成团和组内协调，不提供司机、车辆、配送、支付担保、场地预订或其他线下履约服务。

首批三类：

- 拼同行：找同路同学，一起协商并自行选择合法交通方式；
- 拼运动：找搭子、组队、约运动；
- 拼好饭：约饭、拼桌、凑人数。

## 2. 信息架构

继续使用 Native TabBar：发现 / 社区 / 发布 / 我的。

### 发现

紧凑品牌 Header“今天想拼什么？” → 类型 Chip（全部/拼同行/拼运动/拼好饭） → 统一活动卡片流 → 分页状态。

删除旧“我要拼车/我是司机”视角切换、车辆插画和司机筛选。

### 社区

继续承载校园讨论、安全经验、运动攻略和好饭推荐，不承担活动加入或成团流程。帖子与活动使用不同内容对象。

### 发布

入口页只显示三个纵向场景卡：拼同行、拼运动、拼好饭，选择后进入相应表单。页面底部展示低权重安全边界说明。

### 我的

学生资料/认证 → 我发起的、我加入的、已成团、历史活动 → 当前优先事项 → 收藏、举报记录、安全说明、设置。

删除司机认证、车辆管理、司机任务、接单记录和“我的拼车/司机任务”分段。

## 3. 页面规格

### 统一活动卡片

1. 类型图标 + 类型小 Tag；
2. 生命周期状态；
3. 活动标题；
4. 时间和地点摘要；
5. 人数进度及“还差 X 人”；
6. 一行类型专属摘要；
7. 发起人头像和昵称；
8. 右侧 Chevron，仅进入详情，不在列表直接加入。

卡片统一白底，类型色只用于图标、Tag、短强调线与人数进度，避免三套彩色卡片破坏品牌一致性。

### 类型字段

| 类型 | 专属字段 | 禁止能力 |
| --- | --- | --- |
| 拼同行 | 出发区域、目的区域、出发时间、时间弹性、行李、交通方式倾向 | 司机、车辆、包车、接送、报价、接单 |
| 拼运动 | 项目、场地、水平、强度、器材、时间、人数 | 教练承接、收费陪练、场地代订 |
| 拼好饭 | 餐厅/食堂/商圈、口味、人均预算、忌口、时间、人数 | 外卖、跑腿、代买、支付担保 |

### 活动详情

类型/状态 → 标题 → 时间地点 → 人数进度 → 类型专属信息 → 发起人/成员预览 → 安全说明 → 底部加入按钮。

未认证用户可浏览；点击加入时跳转学生认证分包。满员、过期、取消和下架时底部展示稳定的不可用原因，不从客户端推断。

### 成员空间

只对已成团且仍为有效成员的认证学生开放：活动关键信息、发起人公告、成员列表、轻量文本留言、共享联系方式、安全举报、退出/取消。

第一版不做全站私信。联系方式规则：每位成员主动开启“向本活动成员共享”，只对当前有效成员可见；退出、取消、结束或下架后立即隐藏；不支持二维码图片。

拼同行固定提示：平台仅帮助学生组成同行小组，不提供司机、车辆或运输服务，请自行选择合法交通工具。

## 4. 状态模型

生命周期：草稿 → 招募中 → 已成团 → 进行中 → 已完成；旁路为已取消、已过期、已下架。

达到最低人数进入已成团并开启成员空间；在加入截止前仍可继续招募到人数上限。“已满员”是人数 Badge，不是独立生命周期状态。

## 5. 视觉系统

- 背景：#F5F7F6；品牌主色：#16A36A；白色圆角卡片；
- 拼同行：#3D7FD6，仅作点缀；体素路线节点 + 背包，不使用车辆；
- 拼运动：#705CC8；体素球类 + 运动鞋；
- 拼好饭：#E8873A；体素饭碗 + 餐具；
- 状态色独立于类型色；状态必须同时有文字，不仅靠颜色；
- 继续使用现有 Tab 图标与启动拼图动效。

## 6. 必要视觉资产

| 文件建议 | 用途 | 规格 |
| --- | --- | --- |
| activity-companion.png | 拼同行类型卡/空状态 | 144×144 PNG-32 透明背景 |
| activity-sport.png | 拼运动类型卡/空状态 | 144×144 PNG-32 透明背景 |
| activity-food.png | 拼好饭类型卡/空状态 | 144×144 PNG-32 透明背景 |
| empty-activities.png | 全部活动空状态 | 240×180 或方形透明 PNG |

三类资产必须共享相机、光源、体素颗粒、视觉画布与裁剪留白。图片中不烘焙任何文字。

## 7. 响应式与无障碍

- 320px 下发布类型卡使用左图右文结构，文本容器 `min-width: 0`；
- 卡片不写死高度，标题最多两行，辅助文字自然换行；
- 交互热区不少于约 44px；
- 装饰图 `aria-hidden`，活动卡综合朗读类型、标题、状态、时间、地点和人数；
- 底部操作栏适配 Safe Area；
- 所有页面覆盖 loading、empty、error、disabled、认证拦截、满员、过期、取消、下架状态。

## 8. MVP 边界

第一阶段做：三类活动、统一发现页、类型化发布表单、统一详情、加入/退出/取消、成团成员空间、学生认证、我的活动、举报和内容治理。

暂不做：全站私信、支付、订金、司机/配送员/教练/商家入驻、智能撮合、场地预订、点餐配送、复杂信用分、跨校公开活动。

## 9. 迁移原则

- 通用根对象为“活动”，不能继续以拼车模型为根叠加运动和饭局字段；
- 司机、车辆、履约和承接数据应真正删除或完成受控归档，不能只隐藏前端；
- 成团只代表成员关系成立，不代表交易或服务履约完成；
- 拼车既有字段迁移为拼同行类型扩展，旧司机履约字段不得进入新模型；
- 公开 DTO 不包含联系方式、精确集合说明或成员私密信息。
