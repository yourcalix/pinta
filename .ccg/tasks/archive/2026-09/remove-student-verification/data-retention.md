# 历史学生认证数据处置边界

本次变更只关闭业务访问链路，不在应用发布过程中自动删除生产数据。自动删除可能破坏审计、争议处理或既有留存义务，因此必须由有权限的运维/合规人员单独执行。

上线前确认：

1. 新版本不再读取或写入 `studentVerifications`、`studentVerificationSecrets`、`studentDocumentUploads` 及旧学生证件对象路径。
2. 五个旧学生认证动作统一返回 `NOT_FOUND`，且不进入幂等缓存。
3. 对历史集合和对象存储建立清单，确认法定留存期限、删除责任人和执行窗口。
4. 需要删除时先做只读数量与时间范围核验，再使用独立、可审计、最小权限的迁移任务；不得把删除逻辑放入用户请求链路。
5. 删除完成后由运维输出数量核对与审计记录。本地 Mock 已通过存储键和 schema 版本升级停止读取旧状态。
