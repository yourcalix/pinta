# 需求：站内与服务通知的受控页面直达

## 背景

现有站内通知只包含 `type/activityId/title`，“我的”页点击任何通知都跳活动详情。新申请应进入申请管理页，成团应进入成团页，其他状态通知进入安全详情页。真实订阅模板尚未配置，但目标页面和路由契约可以先在 Mock 与服务端领域层完成。

## 目标

- 建立通知类型到目标页面的唯一 allowlist 映射，不执行通知数据携带的任意 URL。
- `NEW_APPLICATION` 进入申请管理页；`GROUP_FORMED` 进入成团页；批准未成团、拒绝、名额关闭、取消和下架进入详情页。
- 站内通知点击先尝试标记已读；普通标记失败仍允许导航，`ACCOUNT_DISABLED` 等已统一处理错误停止导航。
- 服务端公开通知 DTO 输出稳定的目标语义或安全目标路径，为未来订阅消息发送复用；不得泄露 userId/openid。
- 管理页、成团页和详情页作为冷启动目标时都防御缺失、畸形或无权限参数，不永久 loading、不展示 SDK 原始错误。
- 冷启动不在 `App.onShow` 请求订阅授权，也不创建虚构的模板消息监听器；目标页面自行解析 `id`。
- 保持 `useMock=true` 和空模板 ID，不调用真实发送接口、不触碰官方平台审核。

## 安全边界

- 路由只由受信任的通知 `type` 与不透明 `activityId` 计算；未知类型降级详情页，缺失 ID 降级发现页。
- URL 中活动 ID 使用 `encodeURIComponent`；接收页使用可捕获异常的单次解码。
- 不把 viewerRole、申请备注、联系方式、userId、openid 或运营原因写入路由。
- 后端管理员鉴权、通知归属校验和现有 ACCOUNT_DISABLED 处理保持不变。

## 初步验收

- 每个现有通知类型都有确定、可测试的目标页面。
- 新申请/成团通知分别直达 manage/group，其他通知进入 detail；未知类型安全降级。
- 三个目标页的空 ID 不再卡骨架屏。
- Mock 与 CloudBase DTO 契约一致，自动化覆盖越权、脱敏、编码和点击时序。
- 全量测试、项目检查、CCG 分域复审通过；真实微信服务通知点击保留为真机验收。
