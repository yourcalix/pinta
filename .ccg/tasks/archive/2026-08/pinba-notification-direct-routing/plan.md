# 实施计划

## 1. 契约分析

- 枚举现有及 G3 首发通知类型，确定唯一目标页面与不可达时降级规则。
- 由 GPT 5.5 审查 DTO、身份、路由注入和未来订阅消息复用边界。
- 由网页版 Gemini 3.7 Flash 审查站内点击、冷启动、错误反馈与目标页体验。

## 2. 测试先行

- 新增纯路由映射测试：类型、ID 编码、未知类型、缺失 ID和敏感字段隔离。
- 增加后端与 Mock 通知 DTO 一致性测试。
- 增加“我的”任务点击的标记已读与导航时序测试。
- 增加 manage/group 冷启动缺失与畸形 ID 的状态恢复测试。

## 3. 底层与服务端契约

- 新增最小通知路由模块或稳定 DTO 目标字段，保持 allowlist 和纯函数可测试。
- CloudBase 服务与 Mock 使用一致的通知目标契约，不信任调用方 URL。
- 保持公开 DTO 脱敏和通知归属鉴权。

## 4. 页面接入

- “我的”页按受控目标导航，保留已读失败降级与账号受限阻断。
- 加固 manage/group/detail 的冷启动参数与安全错误状态。
- 不在 App 生命周期中索取订阅授权或执行页面跳转。

## 5. 验证、复审与交付

- 运行专项、后端、Mock、全量测试、语法、结构、diff 与敏感信息检查。
- GPT 5.5 复审后端/安全差异；网页版 Gemini 复审前端实现。
- 修复 Critical/Warning，更新 Spec 与 review.md，归档、提交；完整 G3 代码阶段结束后推送 GitHub。
