# 需求：已下架活动详情页受控兜底

## 背景

服务端与 Mock 已统一：`SUSPENDED` 活动不进入公开列表，直达详情返回错误码 `TAKEDOWN` 和安全文案。当前详情页把所有错误混成一个可重试的通用空状态，导致已下架活动仍显示“重新加载”，形成无意义循环。

## 范围

- 详情页根据错误码区分 `TAKEDOWN` 与可恢复加载错误。
- 已下架状态明确展示“该活动已被处理/暂不可查看”，不展示重试、申请、举报或旧活动内容。
- 网络、超时和普通服务错误继续提供“重新加载”。
- 新一次加载前清空旧活动和业务失效状态，避免旧内容闪现。
- 保持现有 `empty-state` 复用、44px 热区、大字号与读屏语义。
- 增加不依赖微信运行时的页面状态映射测试或静态契约测试。

## 不做

- 不处理 `ACCOUNT_DISABLED` 全局页面；另建任务。
- 不修改后端、Mock、真实 CloudBase 或微信平台配置。
- 不新增视觉资源、动画、UI 框架或外部依赖。

## 验收

- Mock 直达 `a_suspended` 时展示不可重试的已下架兜底。
- 普通加载失败仍显示重试入口。
- 错误状态下不渲染活动详情和任何业务按钮。
- `npm run verify` 全量通过。
