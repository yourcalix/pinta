# 发现页生成素材本地初审

## 文件盘点

- 目录共 20 个 PNG，包含 16 类发现页素材以及原封面、启动立方体和进度条等既有资源。
- `“发布”未激活图标.png` 与 `发布”未激活图标.png` SHA-256 完全一致，属于重复文件且后者文件名缺少左引号。

## 必须进入 Gemini 复核的问题

1. **透明背景不达标**：Hero、汽车、两种起点、两栋校区建筑、品牌标志、两个乘客头像、空位头像及多个 Tab 图标均无 Alpha 通道，视觉上为白底；不能直接叠加到页面卡片。
2. **Tab 状态不成对**：发布激活态为黑底绿色发光图案，与橙色未激活态几何结构不同；发现和我的激活/未激活态也没有保持像素级相同轮廓。
3. **起点形态不一致**：绿色起点是立方体地标，蓝色起点是平铺拼图块，不符合“仅换色”的状态资产契约。
4. **尺寸和比例偏离目标**：多数单图为 1254×1254 或 1448×1086，Tab 图标甚至为 1536×1024；可后处理缩放，但需先解决背景、几何和安全留白。
5. **体积过大**：多数单图约 0.8–1.7MB，尚不适合直接进入小程序主包，后续需裁切透明边界、缩放并压缩。

- 绿色品牌拼图、绿色起点方块和空位头像的语义清楚，可在透明化后继续评估。

## Gemini 反馈校正

- Gemini 认为“全套素材均无 Alpha”不准确。本地 `sips` 检测确认：发布未激活、发现未激活、我的激活等文件已有 Alpha；其余多数新素材确实为白底或黑底。
- Gemini 认为起点、校区建筑和绿色汽车缺失不准确，这些文件均已存在于目录中。
- Gemini 认为 Hero 必须生成完整 3:1 图片不作为硬约束：生产 Hero 是 WXML 左侧真实文字与右侧插画组合，右侧插画可继续使用近 4:3 的透明构图。
- “发布”激活态黑底发光且结构失配、绿色/蓝色起点几何结构不一致，属于真实阻断问题。

## 主会话唯一建议

### 必须重新处理

1. 以橙色发布未激活图标为几何母版，生成完全同轮廓的品牌绿色激活态，禁止黑底和发光。
2. 以绿色立方体起点为母版，仅换色生成蓝色版本。
3. 对所有白底素材建立真实 Alpha；浅色建筑、脸部和空位头像不得使用会误删浅色边缘的一键粗糙抠图。

### 可以保留并规范化

- Hero 保留当前构图，通过高质量背景移除或 Image 2 精确编辑得到透明版本，不强制改为完整 3:1 场景图。
- 绿色汽车、两栋校区建筑、乘客头像和品牌拼图保留当前造型。
- 已带透明通道且轮廓可接受的图标先保留，导入前统一裁边、缩放和压缩。

### 推荐产品决定

- 发布 Tab 激活态使用品牌翠绿 `#16A36A`，未激活态保持橙色。
- 优先保留透明 Alpha 内的柔和接触阴影；若背景移除产生白边或灰边，则移除污染阴影并改用统一 CSS `drop-shadow`，不以牺牲边缘质量为代价。
