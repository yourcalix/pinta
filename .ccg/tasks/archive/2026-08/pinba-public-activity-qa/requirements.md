# 需求：活动详情公开问答区

## 背景

发布草稿恢复与发现页分页/过期一致性已经完成。按照既定 V1.1 优先级，下一项实现活动详情公开问答，解决拼车行李、商品自提、搭子装备等批准前的公共信息沟通问题。

## MVP 目标

- 活动详情公开展示与该活动关联的问题及发起者回答。
- 游客可以阅读；提问属于受保护写操作，按动作登录并经过内容安全检查。
- 仅活动发起者可以回答，服务端强制鉴权；问题和回答均使用安全公开 DTO。
- 不把联系方式、openid、内部风控字段、审核详情或原始 SDK 错误暴露给客户端。
- 支持明确的 loading、empty、提交中、失败恢复和只读状态。
- Mock、Memory Store 与 CloudBase 保持同一 API 契约，继续保持 `useMock=true`。

## 建议的最小范围（待 CCG 分析确认）

- 单层问答：一个问题最多一个发起者回答，不做追问、楼中楼、点赞、编辑或删除。
- 问题按创建时间倒序，首版设置明确数量上限或安全分页，不一次性无限加载。
- 活动被下架时不返回问答；不可继续交互的活动保留历史问答阅读但关闭新增提问/回答，具体状态白名单由后端分析确认。
- 问题和回答均进入现有 Moderation 端口；生产环境内容安全不可用时继续 Fail-closed。
- 是否在本阶段加入问答举报、通知和频控，由安全/复杂度分析后做最小化取舍。

## 验收边界

- 越权回答、重复回答、跨活动引用、下架活动读取、幂等重试和内容违规均有自动化测试。
- 游客读取与登录后提问链路不互相阻塞；回答失败不会丢失输入。
- 320px、小屏大字号、键盘遮挡、Safe Area、读屏语义和 44px 触控热区完成前端复审。
- 全量测试、CCG 双域复审、任务归档、提交并推送 `origin/main` 后交付。
