# 需求：受限账号全局受控反馈

## 背景

后端与 Mock 已统一返回 `ACCOUNT_DISABLED`，但页面目前各自捕获错误并显示 Toast。若直接在请求层增加 Modal，容易与页面 Toast 重叠；若只依赖各页面处理，又容易遗漏入口并残留失效登录态。

## 目标

- 任一需要身份的操作收到 `ACCOUNT_DISABLED` 时，统一清除客户端会话作用域与 `globalData.user`。
- 同一时刻只展示一个受控提示，不因并发请求出现多个 Modal 或重复 Toast。
- 提示文案不暴露内部风控原因，不提供申诉、设置页或其他尚未实现的入口。
- 用户确认后返回稳定的发现 Tab；游客浏览能力继续可用。
- 页面 pending/loading 状态必须通过既有 `finally` 或错误分支恢复，不能因统一处理器吞错而卡住。
- 未受限错误继续使用各页面既有安全提示。
- Mock 增加可自动验证的受限账号交互契约，不切换真实 CloudBase。

## 明确不做

- 不修改后端 `ACCOUNT_DISABLED` 判定或错误文案。
- 不新增申诉中心、客服、封禁原因详情或后台管理页面。
- 不修改微信官方平台、真实 AppID、CloudBase 环境或审核状态。
- 不把游客公开列表和公开详情改成强制登录。

## 验收

- 并发两个 `ACCOUNT_DISABLED` 错误只展示一次 Modal。
- 受限错误不会再叠加页面 Toast；普通错误仍正常提示。
- 全局用户和 API 会话作用域被清理，确认后切换到发现页。
- 所有受保护页面的 loading/pending 可恢复，无白屏或按钮永久禁用。
- `useMock=true` 保持不变，`npm run verify` 全量通过。
