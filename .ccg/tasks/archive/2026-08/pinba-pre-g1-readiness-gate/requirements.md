# 拼吧进入 G1 前的就绪门槛需求

## 目标

把 G0 代码交付转化为可执行、可记录、可判定的 G1 入口门禁，区分自动检查、微信后台人工配置与真实设备验收，避免在真实 AppID、隐私指引或真机链路未就绪时提前切换 CloudBase。

## 范围

- 检查本地真实 AppID 私有覆盖是否存在且不进入 Git。
- 检查公共配置继续保持 `touristappid`、`useMock=true`、空 CloudBase 环境和空订阅模板。
- 完善微信后台的账号成员、品牌资料一致性、账号健康状态、服务类目、UGC 场景声明、隐私保护指引、内容安全、订阅模板和云环境准备清单。
- 把备案、认证与主体适用性作为提审上线前置规划项；账号涉嫌违规或能力受限仍是 G1 硬阻断。
- 为 iOS/Android 隐私授权与成团联系方式流程提供可填写的真机验收记录。
- 增加一个只读的 G1 就绪检查命令，输出 PASS / MANUAL / BLOCKED，不写入真实标识或密钥。
- 明确只有自动检查通过且人工硬门槛有证据时，才允许创建 G1 切换真实 CloudBase 的任务。

## 不做

- 不在本任务中切换 `useMock=false`。
- 不创建集合、不部署云函数、不写入 CloudBase 环境 ID 或订阅模板 ID。
- 不代表用户接受微信协议、提交隐私指引、变更账号成员权限或上传审核版本。
- 不把开发者工具模拟结果当作 iOS/Android 真机结果。

## CCG 输入

- 后端、配置与门禁逻辑由 GPT 5.3 Codex Spark 分析和复核。
- 前端真机矩阵直接承接上一轮用户贴回的网页版 Gemini 3.6 结果；若本轮修改前端代码超过审查阈值，再生成新的网页版 Gemini 复核提示词。
- GPT 5.6 Sol 主会话综合实施、验证、记录与归档。
