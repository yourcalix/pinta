# 分析结论

## CCG 外部分析状态

- 已按配置调用 GPT 5.5 后端 analyzer。
- 外部通道连续无正文输出，最终返回远端会话记录错误并被终止；未伪造外部结论，也未把远端会话标识写入仓库。
- 本任务依据已读取的后端 Spec、现有实现和回归测试继续推进。

## 代码证据

- `requireActiveUser` 当前把“用户不存在”和“用户非 ACTIVE”都映射成 `UNAUTHENTICATED`，无法让客户端区分账号限制。
- `auth.login` 通过 `ensureUser` 后直接成功，已有受限用户会被放行。
- 写操作先读取幂等缓存、后进入业务动作；账号在首次成功后被停用时，同一幂等键可能返回旧成功结果。
- `activity.detail` 当前把 `SUSPENDED` 映射成 `NOT_FOUND`；公开列表已经只允许 `RECRUITING | FORMED`，天然排除下架活动。
- Mock 的 `requireUser` 只检查用户是否存在，部分受保护动作也未统一执行该检查；Mock 与云函数契约不一致。

## 最小实施边界

1. 增加 `ACCOUNT_DISABLED` 与 `TAKEDOWN` 的稳定安全文案。
2. 登录、资料读取和全部写操作明确检查账号 ACTIVE；写操作在命中幂等缓存前检查，避免停用后重放成功。
3. 下架活动直达详情返回 `TAKEDOWN`，公开列表继续隐藏。
4. Mock 增加受限账号和下架活动测试种子，并统一保护非公开动作。
5. 公共 DTO 不输出 `suspension`、管理员标识、联系方式或内部幂等字段。
