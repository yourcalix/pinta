# “拼吧”最小 MVP——CCG 总体计划

## 1. 产品设计与审核

- 完成 GPT 5.3 Codex Spark 后端分析。
- 完成网页版 Gemini 3.6 前端体验分析。
- 由主会话综合形成项目设计书、MVP 边界、待决策项与验收指标。
- 根据用户审核意见修订基线。

## 2. 工程与规格建立

- 检查/建立 `.ccg/spec` 前后端规范。
- 确定微信原生小程序与后端方案。
- 建立目录、配置、环境示例、数据 schema 与测试骨架。

## 3. 后端最小闭环

- 身份与用户资料。
- 活动/拼局发布、查询和类型扩展。
- 申请、审批、名额并发、成团、取消、过期和完成状态。
- 举报、基础审核、审计与频控。
- 单元/集成测试。

## 4. 小程序前端最小闭环

- 首页/发现、分类筛选、详情。
- 发布流程及三类场景字段。
- 申请、审核、成团与状态反馈。
- 我的发布、我的参与、通知、举报与基础资料。
- 空状态、错误状态、隐私提示和安全提醒。

## 5. CCG 审查与修复

- GPT 5.3 Codex Spark 审查后端、安全、数据和业务状态。
- 网页版 Gemini 3.6 审查前端、交互、WXML/WXSS 和可用性。
- 主会话合并问题，修复 Critical/Warning，并重新验证。

## 6. 验证、打包与交付

- 完整测试、类型/语法检查、构建与关键流程手工验证。
- 提供本地运行、微信开发者工具导入、环境配置和演示数据说明。
- 归档 CCG 任务；当前目录不是 Git 仓库时记录无法提交的限制。
