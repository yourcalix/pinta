# “拼吧”初步项目设计书——CCG 计划

## 阶段 1：需求分析

1. 主会话整理用户目标、假设、设计书结构与审核点。
2. GPT 5.3 Codex Spark 从业务规则、后端架构、领域模型、状态机、安全与合规风险角度分析。
3. 网页版 Gemini 3.7 Flash 从小程序信息架构、页面、视觉、交互与用户旅程角度分析。

## 阶段 2：方案综合

1. 合并两端意见，识别冲突、过度设计和遗漏。
2. 确定 MVP 场景边界、通用活动模型与差异化字段。
3. 明确必须由用户审核的产品决策，不擅自把假设写成定论。

## 阶段 3：设计书成稿

1. 在 `outputs/` 生成 Markdown 初稿。
2. 覆盖产品、体验、业务、技术、风控、运营、指标和路线图。
3. 以表格、Mermaid 流程图/状态图等方式表达复杂关系，但控制可读性。

## 阶段 4：验证与交付

1. 逐项核对增强需求与设计书目录。
2. 检查业务状态、数据实体、页面和接口的一致性。
3. 记录 CCG 分析与审查结论。
4. 完成任务归档；若目录不是 Git 仓库，则保留文件并明确记录无法提交。
