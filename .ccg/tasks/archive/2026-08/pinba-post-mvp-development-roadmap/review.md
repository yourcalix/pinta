# 拼吧 MVP 后续开发计划 CCG 审查

## 审查范围

- 基于已完成的代码级 MVP 制定 G0—G4、V1.1 和 V1.2 路线。
- 后端、数据、安全与运维：GPT 5.3 Codex Spark 架构分析。
- 前端、交互与真机路线：网页版 Gemini 3.6 用户手动回传复核。
- 综合、事实校正和最终文档：GPT 5.6 Sol 主会话。

## 外部模型执行记录

GPT 5.3 Codex Spark 在读取工作区时曾出现 3 次 `/bin/zsh: No such file or directory` 的外部工具错误；其后基于任务上下文成功返回完整路线分析，未修改工作区。主会话使用仓库真实文件复核了其建议后再纳入计划。

Gemini 3.6 最终结论为【调整后可执行】，问题分级为 Critical 0、Warning 1、Info 1。Warning 指向分享卡片冷启动时全局初始化与详情请求的竞态；Info 指向 iOS/Android 剪贴板系统反馈差异。

## 综合采用项

1. 将实际使用隐私能力的授权回调、拒绝降级和隐私弹窗前移至 G0。
2. 将详情分享、微信聊天卡片冷/热启动解析和全局初始化等待前移至 G2。
3. 将订阅消息目标页面、活动下架和账号受限兜底前移至 G3。
4. V1.1 严格重排为：发布草稿、分页与状态一致性、公开问答、最小筛选。
5. 高级联合筛选继续删除；公开问答继续留在灰度之后。

## 主会话校正项

1. 当前产品不使用手机号授权，因此不因隐私适配新增手机号或其他未来能力的权限请求。
2. 真实页面路径是 `subpackages/...`，活动查询参数沿用当前契约 `id`；实施时不得照搬反馈中的 `subpages` 或另造参数名。
3. 订阅消息由服务端写入目标 `page`，目标页面解析启动参数并等待初始化；`App.onShow` 只作恢复辅助，不描述为“模板消息监听器”。
4. CloudBase 调用使用稳定领域错误码和统一错误映射，不假设传统 HTTP 状态码。
5. 不直接采用“每天取消 3 次、撤回 5 次”等未经灰度数据验证的硬阈值；先观测并保留可配置限流能力。
6. 剪贴板复制只保留系统级成功提示，实施时避免叠加重复 Toast。
