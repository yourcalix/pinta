# 拼吧 G0 真实账号与隐私基线需求

## 本阶段目标

在不进入真实数据库迁移和业务功能扩张的前提下，完成正式小程序接入前的账号、合规、隐私交互与环境配置基线，使 G1 可以安全切换到真实 AppID 和 CloudBase。

## 范围

- 盘点并文档化 AppID、服务类目、隐私保护指引、用户协议、内容安全、订阅模板和测试/生产云环境依赖。
- 对仓库内环境配置进行无密钥、可校验的分层设计；真实 AppID、环境 ID 和模板 ID 不进入 Git。
- 盘点实际使用的隐私相关微信 API，只为现有能力适配授权回调和拒绝降级，不新增手机号、位置、头像等权限。
- 为成团页复制联系方式等实际操作设计并实现最小隐私弹窗/授权恢复机制，覆盖同意、拒绝、重复请求、旧基础库或平台能力不可用。
- 补充相应自动化/静态检查和 G0 手工验收清单。

## 明确不做

- 不在 G0 切换 `useMock=false`，不创建生产集合或部署生产云函数；这些属于 G1。
- 不把真实 AppID、CloudBase 环境 ID、订阅模板 ID 或任何密钥提交到仓库。
- 不接入手机号、精确位置、通讯录、头像或二维码能力。
- 不实现 G2 分享冷启动、G3 订阅直达/举报运营和 V1.1 功能。

## 验收原则

- 游客浏览不被隐私弹窗打断。
- 只有用户主动触发受隐私规则约束的能力时才请求授权。
- 拒绝后中止本次敏感动作但不影响浏览、返回和其他非敏感功能。
- 隐私文案、真实接口调用和小程序后台声明保持一致。
- Mock 模式与现有 23 项核心测试继续通过。
- CCG 路由：后端/配置由 GPT 5.3 Codex Spark 分析，隐私 UI 与交互由网页版 Gemini 3.6 复核，GPT 5.6 Sol 综合实施。
