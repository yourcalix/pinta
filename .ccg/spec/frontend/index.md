# 拼吧微信小程序前端规范

## 技术边界

- 使用微信原生小程序 JavaScript，直接导入微信开发者工具运行，不依赖本地编译步骤。
- 主包只放 Tab 页面；详情、发布表单、申请管理、成团和举报使用分包。
- 页面不得直接调用 `wx.cloud.callFunction`；统一通过 `miniprogram/services/`。
- 默认启用 Mock Service，使 `touristappid` 下也能走通 MVP；切换 Cloud 模式时页面代码不变。

## 信息架构

- 首页问候栏相对内容流上移 `44rpx`，只承载头像、昵称与欢迎文案。消息/搜索双按钮必须放在 Hero 右上角：标准屏为 `144×64rpx`、定位 `top: 40rpx; right: 38rpx`，与 Hero 左侧“你的搭子”标题上边界共线；320px 为 `132×58rpx`、定位 `top: 30rpx; right: 28rpx`。首页内容层继续使用累计 `-48rpx` 光学上移且不得修改全局安全区算法。Hero 使用活动卡压缩后释放的纵向空间继续向下伸展：标准屏高度为 `709rpx`、320px 为 `652rpx`，使快捷卡和“附近拼吧”整体下移、但三张活动卡底边仍维持在悬浮 TabBar 上方约 `16rpx` 的安全距离。首页为单屏固定视口，页面配置必须启用 `disableScroll`、关闭下拉刷新，根节点同时锁定 `100vh` 并裁切纵向溢出。
- 首页 Hero 正式主视觉使用本地透明 PNG `hero-community-puzzle.png`，采用 `aspectFit` 保留完整人物和场景边缘；发布素材固定为 `600×1200` 的 1:2 竖图。标准屏槽位 `430×860rpx`、锁定 `right: 0; bottom: -122rpx`，320px 槽位 `373×746rpx`、锁定 `right: 0; bottom: -114rpx`，使图片物理底边与三张快捷卡底边严格齐平。插画下部从重叠区起点附近（约 74%）渐隐，至快捷卡底边完全透明；插画仍位于 Hero 文案层下和快捷卡层下，不得遮挡卡片文字与交互。“附近拼吧”紧跟快捷卡：快捷卡下间距 `8rpx`、章节栏高 `64rpx`；三列活动卡按宽高 `1:1.25` 设计，标准屏为 `220×275rpx`、320px 为 `192×240rpx`，骨架屏必须保持同尺寸。
- TabBar 固定为“首页 / 发现 / 发布 / 消息 / 我的”五栏；为避免迁移风险，`pages/discover/index` 保持首页物理路由，`pages/community/index` 保持发现物理路由。“发布”保持第 3 项视觉中心，“消息”固定在发布与我的之间。底栏使用微信官方 `custom-tab-bar`，五个 Tab 页必须在 `onShow` 同步选中态。
- 首页使用 `#F9F7F2` 暖米白生活方式视觉，正文顺序固定为动态头像昵称问候栏、生活方式 Hero、与 Hero 负边距叠放的三张快捷卡、真实活动流。首页不申请定位，活动章节固定使用“正在组队 · 全城热拼”，不得在无定位上下文声称“附近”。搜索仅使用 Hero 内右对齐锚定浮层，不得再在快捷卡下方插入搜索或类型筛选面板。Hero 与三列活动预览的既有几何契约保持不变。三张快捷卡固定为“组队拼团 / 看看大家都在聊什么”“琐碎回忆 / 记录第一次成团”“暂定 / 模块占位”；第一张以防重复入栈的 `navigateTo` 进入 `subpackages/activity/list/index` 全城列表，第二张进入 `subpackages/activity/memories/index` 静态专题预告页，第三张必须为不可点击占位。真实 UGC 契约上线前不得伪造故事、天气、通知、邻里图片或统计。
- 发现 Tab 使用同源暖米白背景和黑色状态栏文字，顶部为 `PINBA DISCOVER` 标识、发现标题与黑色发帖胶囊，下接只读发现守则、单一真实“正在发生”栏目和白色纯文字帖子流。不得伪造热门话题、分区、置顶、浏览量、帖子配图或“新回 / 我发 / 我赞”等无数据源 Tab。帖子正文默认最多三行并支持连续字符断行，整卡是唯一详情导航热区，底部只展示真实点赞数与回复数；列表头像继续使用昵称首字与受控低饱和色盘。顶部继续复用页面根节点 `contentTopInset`，不得重复叠加状态栏高度。
- 发布 Tab 使用深蓝纸纹沉浸背景、紧凑手绘标题和每行两个模块的双列自动换行网格；“拼同行 / 拼运动 / 拼饭桌”整卡直接进入对应表单，不叠加搜索、筛选 Chip 或重复详情卡。奇数个模块的末项保持左对齐，不渲染伪占位卡；双列卡片继续保持原画廊约 304:430 的纵向比例、完整画布插画与原有图文层级，不得为了压缩首屏把场景插画缩成底部小图标。模块插画统一从生图与导出阶段使用 600×750 透明画布并校准主体安全框；同为横向双人场景时，有效主体参考约 480×440px、左上约 60×210px，默认共用基础插画槽位，不为单卡追加补偿性缩放。仅在存在真实且有意义的本地草稿时展示最近草稿快捷条，底部保留轻量安全边界提示；装饰插画退出事件与无障碍树，整卡提供完整入口语义。
- 三类发布表单共用一个沉浸式动态页面：深蓝纸纹覆盖完整视口，使用自定义返回导航并复用胶囊安全区计算；顶部不显示“发布……”页面标题，返回操作仅显示无底色、无边框箭头，但继续保留完整触控热区与无障碍名称。正文只显示类型副标，不重复渲染页面大标题或旧品牌图。通用、专属、时间人数和安全规则使用奶油白纸片分组，场景差异仅体现在副标、章节标记和选中 Chip；底部固定提交栏必须为正文预留完整滚动安全区，所有输入控件统一配置键盘顶升与光标间距。已定稿的“拼饭桌”原稿是该动态页的独立视觉分支，允许使用 `pin_food_interface.jpg` 整纸背景、`fapiao.png` 卡片和现有插画/文案；共享纸纹只作为其底层容灾，不得以旧版四段撕边纸 DOM 断言覆盖当前定稿界面。视觉例外不豁免真实数据契约、装饰层触控退出、键盘顶升或底部安全区要求。
- 已定稿的“拼同行”原稿同样使用物理隔离的 `type === 'companion'` 分支，固定为“基本信息 / 同行信息 / 同行偏好 / 时间与人数 / 参与规则与安全”五张旅行手绘纸卡。旅行边框使用发布分包内 9:20 透明安全画布并退出触控和无障碍树；日期、时间和弹性使用原生 Picker。人数文案必须明确为“不含发起人”的 1—19 位拼友，固定人数或严格递增范围在提交时加 1 映射为总人数 2—20。九项同行偏好均为可再次点击取消的选填严格枚举；不得迁入活动图片上传、免审核开关或伪造的十分钟结束时间。拼运动与拼饭桌分支不得消费同行字段。
- 澳门校园拼车发布采用单页长表单，顺序固定为路线、出发时间、容量与个人行李、本人电话、补充说明与安全协议；不再展示步骤进度条或上一步/下一步。公开标题由固定路线确定性生成，报名截止由提交适配层设为接车时间窗开始前一秒，保持现有通用活动契约且无需用户填写。
- “我的”使用受控头像放大柔化形成静态沉浸背景，叠加头像、昵称、成年标签、兴趣摘要和发起/加入/成团三项真实统计；沉浸背景必须从视口顶部通顶，页面根节点不得用 `contentTopInset` 推开整块背景，安全区只由头部内容层承担。页面根节点上下内边距必须显式归零，底部 TabBar 与 Safe Area 避让只由下方暖米白内容面板承担，避免重复留白露出全局纸纹。顶部优先展示待审批、已成团和即将开始任务，无待办时整行折叠。下半区使用 #F9F7F2 暖米白大圆角面板、白色活动卡与“发起 / 参与 / 成团 / 历史”四栏活动时间线；成员头像、人数与真实状态置于卡片底部，日期单独作为时间线标题。分类显示数量最多99+，无障碍保留真实完整数量；下方样式必须限定在 .profile-content-sheet，保持上方背景、资料、统计及待办原样。正文28rpx起、辅助24rpx起，窄屏分类数量另行，面板底部200rpx加SafeArea，不新增关注、粉丝、奖牌、评价或俱乐部等无事实源字段。
- “消息”主页将系统通知与一对一私信分区展示；打开消息 Tab 不得直接清除未读，只有具体会话成功标记已读后才更新 Badge。未读摘要刷新失败时保留上一个已确认数值，不可伪造为 0。
- 一对一私信页使用沉浸式自定义导航与固定视口纸纹背景，不显示 TabBar；共同活动只使用紧凑单行纸条，举报入口位于纸条右侧并保持至少 44px 热区，不与微信胶囊争抢导航空间。消息按发送者与 3 分钟时间窗分组，连续消息隐藏重复头像与时间；气泡必须支持连续英文、数字和无空格字符断行及文本选择。输入区只支持最多 500 字纯文字，发送失败保留草稿并局部提示；键盘聚焦与发送成功后锚定最新消息，成员关系失效时主动收起键盘并替换为只读提示。私信不展示在线状态、已读回执，也不使用大型活动卡。
- 活动详情使用参考式高幅海报与纯白连续面板：海报面板起点约为同视口高度的 75%；当前 600×750 透明插画必须使用 `aspectFit` 并由活动类型底色承接空余区域，避免在长屏容器裁掉人物和器材。白色面板以负外边距覆盖海报下缘。底栏顺序固定为“成员群聊 / 咨询发起人 / 原生分享 / 黑底亮绿主操作”，无支付语义；三枚工具键实际热区不小于 88rpx，窄屏主操作保持单行省略。活动详情是全站纸纹背景的显式例外，页面 JSON 使用白色占位；系统状态栏与微信胶囊仍由微信提供，不仿制。
- 成员群聊页面隐藏或卸载时必须清空消息、成员 generation、输入草稿和滚动锚点，并停止轮询；再次显示从服务端重新鉴权。旧周期在途响应不得恢复到新周期页面。终态显示只读提示，下架或退出清空历史并进入安全错误态。
- 通知点击只接受 `MANAGE | GROUP | DETAIL` 语义目标并由本地页面白名单生成路径；未知目标降级详情，缺失 ID 返回发现页，不执行服务端或通知记录携带的自由 URL。
- 活动分享只使用公开标题与编码后的不透明活动 ID；详情未加载、参数无效、网络错误或活动下架时，分享卡片统一降级到发现页，不传播失效详情或任何 viewer/contact 字段。
- 澳门拼车发现页的一级分类固定为“全部 / 凼仔校区 / 金龙校区”三个等宽校区 Chip，不在首页展示 8 条路线 Chip；具体路线仅用于发布滚轮、行程卡片和详情。切换乘客/司机视角保留校区筛选，清除筛选同时清空校区与搜索草稿。
- 澳门校园拼车发布页只读展示固定 7 个乘客名额，司机不计入人数；发现页乘客主徽标只使用“招募中 / 已满员”，不得残留“已成团·可加入”等旧文案。
- 澳门拼车发布者与直接入团乘客都必须在页面内选择“我的行李”，选项固定为“无行李 / 小行李 / 大行李”，初始不默认选中；提交失败保留选择，成功后以服务端 `viewerMembership.luggageType` 回填。活动级旧“行李规则”不再展示或提交，历史缺失值显示“未填写”而不是推断为“无行李”。

## 状态与数据

- 服务端是业务事实来源；页面在 `onShow` 或关键动作后重新拉取，不用 EventBus 维护关键状态。
- 社区列表只展示帖子点赞数与回复数，整卡保持唯一导航热区；帖子和一层回复的点赞只在详情执行。详情按目标使用独立 pending 锁，乐观更新失败时精准回滚，成功后以服务端返回的点赞状态和计数为准。
- 社区详情必须消费回复复合游标，续页按 ID 去重并保持 `createdAt + id` 正序；续页失败只显示页尾局部重试，不清空已加载帖子和回复，刷新请求必须使旧续页响应失效。
- 私信仅在页面可见且可发送时串行低频轮询；离屏清理定时器并使晚到响应失效。最新消息按 ID 合并、跨页追赶到上次服务端快照，不得让本地发送结果充当追赶边界而漏掉中间消息。阅读历史不强制跳底也不确认未见新消息；同正文失败重试复用当前页内 clientMessageId，成功回包不得擦掉用户新编辑的下一条草稿。已确认未读快照必须按会话身份隔离，网络失败不得清零。
- 所有页面必须显式覆盖 loading、empty、error 和业务失效状态。
- 全局请求层已经向用户反馈的错误必须标记为 `error.handled` 后继续抛出；页面据此抑制重复 Toast 或原始文案，但仍须通过 `finally` 或安全错误分支恢复 loading、pending、submitting，并清空不可继续展示的旧业务数据。
- 业务失效状态使用稳定错误码分支，不比较展示文案；重复加载前清空旧业务数据，并用请求序号阻止过期响应覆盖新状态。
- 详情页公开问答使用独立请求序号和局部 loading/empty/error/ready 状态；问答失败不得清空活动详情或阻断申请、管理、成团等主链路。写入成功后重新拉取服务端事实，不做问答乐观插入。
- 分享冷启动先在页面 `onLoad` 防御性解析路由参数，再由页面生命周期加载公开详情；只有存在真实异步全局依赖时才建立 readiness Promise，不为同步初始化或公开读取制造空等待层。
- 服务通知直达页必须兼容单页面栈：无权限可 `redirectTo` 公开详情，不存在或下架时 `switchTab` 返回发现；不得依赖 `navigateBack`。受保护目标页需在空 ID 时结束 loading，并用请求序号丢弃离屏或过期响应。
- 提交按钮具有 pending 防重；失败保留表单和用户输入。
- 非拼车申请按钮继续说明获批占位；澳门拼车详情使用“立即加入拼车”，不得展示备注、同意勾选、等待审批或发起者批准入口。
- WXML 不执行除法等需要边界保护的展示计算；进度百分比、剩余数量和读屏文案在 JS 装饰层预计算并限制合法范围。
- 拼车加入与退出按钮只消费服务端 DTO 的 `canJoinRide`、`canLeaveRide` 与 `rideExitLocked`，不得由前端自行推导。若响应缺少布尔型 `canJoinRide`，必须 fail-closed 并提示服务版本异常，不得回退到 `RECRUITING` 或剩余名额推导。司机确认后已有成员显示静态退出锁定说明，但未满 7 人且 `canJoinRide` 为真时，新乘客入口继续开放。
- 拼车管理页不展示申请审批列表，改为展示当前容量、司机承接状态和“乘客直接加入，无需审批”说明；非拼车管理页保持原申请流。
- 拼车展示层只有 `RECRUITING` 与 `FORMED` 可按剩余名额归一为“招募中 / 已满员”；`CANCELLED`、`EXPIRED`、`IN_PROGRESS`、`COMPLETED`、`SUSPENDED` 等生命周期状态必须优先保留服务端状态语义，不得被人数覆盖。
- “我的”等聚合页每次刷新都必须生成请求序号，仅最新请求可更新页面；页面隐藏或卸载时使在途响应失效，防止旧快照覆盖取消、退出等新事实。
- “我的”页不展示身份认证横幅或锁定卡，登录后直接呈现个人资料、活动统计、待办通知和活动列表。活动与通知使用独立异步结果：通知失败只隐藏红点或待办区，不得使主要活动数据进入全局错误态。
- 个人资料生日为可选私密原始字段，使用严格 `YYYY-MM-DD` 保存且完整值只进入本人 DTO；填写后必须按澳门自然日校验年满 18 岁。用户发起活动时，详情名片可仅展示服务端派生的 `18–150` 整数年龄，但编辑页必须明确告知“完整生日仅自己可见、活动中公开年龄”；成员快照、分享、审计与日志仍不得携带完整生日。历史资料缺失时显示“未填写”，旧客户端省略字段更新时保留已有生日；编辑端以受控年月日滚轮物理限制成年上界，不展示或推导星座。
- 发起人名片可展示当前受控头像、性别、派生年龄与用户主动设置的标准 MBTI；缺失字段静默隐藏，不显示未知占位。性别与年龄合并为中性标签，MBTI 单独为中性标签；编辑 MBTI 时必须告知其会显示在用户发起的活动名片中，清空后不展示。整卡无障碍文案聚合上述公开资料，装饰标签退出读屏焦点。
- “我的”页的司机认证状态与司机任务列表必须独立加载和降级。只有司机资料与申请接口成功并明确返回空值时才可展示“开始司机认证”；接口失败不得用 `null` 冒充未提交。已确认的 `driver.canAcceptRide === true` 或非空司机申请均可作为权威状态保留，任务列表失败只在任务区域局部提示重试。
- 发布和申请加入仅检查登录、账号可用、基础资料完整与成年确认，不得再请求学生认证状态、捕获学生认证错误码或跳转学生认证分包。游客仍可只读浏览公开列表与详情。
- 已删除的学生认证页面、路由、服务和前端拦截器不得以兼容代码形式保留；资料卡也不得使用“校园互助用户”“已认证学生”等标签暗示不存在的身份背书。

## 隐私与安全

- 列表和详情零登录浏览；发布、申请、我的按动作触发登录。
- 首屏不请求位置、手机号或头像权限；城市和区域手动选择。
- 联系信息不随详情加载；仅在成团页由用户主动点击后请求，首次显示一次安全确认。
- 不展示未验证的实名、信用或手机号徽章。
- MVP 仅开放“本人头像”这一受控 UGC 图片上传用途：必须由用户主动通过微信头像选择能力触发；个人资料页选择或恢复头像只形成本页草稿，必须与其他资料统一在“保存资料”后才调用头像写接口，直接返回不得改变服务端头像。上传经过服务端签发路径、文件校验和图片安全审核后，可作为活动人数进度中的当前成员头像展示；前端只消费 `CUSTOM | DEFAULT | EMPTY`，CUSTOM 破图单次回退到性别对应手绘头像，旧 `PASSENGER_A/B` 与像素头像路径不得进入最终渲染。活动封面、社区配图、群二维码与举报证据仍禁止上传；自定义头像不得进入社区、申请、群聊或分享 DTO。
- 微信隐私接口按实际动作请求，不在首屏预授权。`wx.onNeedPrivacyAuthorization` 是覆盖式监听且没有对应的 off API；用单例桥接管理当前活动组件，注册后每个请求都必须以 `agree` 或 `disagree` 结算。
- 剪贴板授权只控制 `wx.setClipboardData` 等本地能力，不进入服务端成员权限契约。拒绝或旧基础库降级时，必须保留可选中文本等真实可用的非敏感替代路径。
- 司机证件号与认证图片引用不得写入 Local Storage；上传成功后页面只保存短期 uploadId，sealed 文件地址只存在服务端。敏感写请求的本地幂等指纹必须不可包含或复原完整 payload。
- 拼车发布者与直接入团乘客必须填写受控区号的本人电话；电话输入失败时保留、提交成功或页面销毁时清空，不进入草稿、Local Storage、分享参数、日志或公开详情。成员电话列表仅在当前承接司机的详情视角按需加载，页面隐藏、卸载、切换乘客视角或取消承接时立即清空，并用独立请求序号丢弃晚到响应。
- 已下线的学生身份数据不得写入新的本地草稿、缓存或页面状态；历史客户端缓存通过存储版本迁移停止读取，服务端历史敏感数据由独立的数据治理流程处理。

## 视觉与可访问性

- 品牌主色使用独立绿色 `#16A36A`，避免暗示与微信官方存在隶属关系。
- 除首页、发现、参考式活动详情与资料编辑等独立视觉页面外，其余页面复用主包根路径 `/assets/images/shared/shared-paper-bg.jpg`。独立视觉页面必须在 JSON 与页面根节点同时声明自身托底色，避免切页闪白；背景装饰退出触控与无障碍树。
- 场景色：拼车蓝、拼商品橙、拼搭子紫；状态不能只靠颜色表达。
- 自定义 TabBar 五列必须各占 20% 热区，不得互相覆盖。底板为左右 `24rpx`、底部 `calc(24rpx + env(safe-area-inset-bottom))` 的白色悬浮胶囊；普通入口使用受控黑色 RGBA PNG，选中态保持 `opacity: 1`，未选中统一降为 `opacity: 0.42`，不得使用 CSS filter 动态着色。选中态使用黑色文字与黄色小圆点；黄色圆点必须参与纵向 Flex 布局并为未选中项保留透明占位，避免大字模式压住文案。中央发布只显示黑色正圆与受控白色 PNG 加号，不显示“发布”文字，但整项继续保留“发布新拼单”无障碍名称；消息入口继续为未读徽标留出空间。页面正文底部必须至少预留 `calc(180rpx + env(safe-area-inset-bottom))`。
- 启用 `tabBar.custom: true` 后，业务页面不得调用 `wx.hideTabBar()` 或 `wx.showTabBar()`；真机可能因此重新唤醒原生底栏并与 `custom-tab-bar` 重复渲染。启动覆盖层等临时显隐需求统一通过 `getTabBar()` 获取自定义组件并修改组件内部状态，异常退出时必须恢复可见。
- 正文最小 `28rpx`，辅助文字最小 `24rpx`；交互热区不小于约 44px。
- 固定底部操作区适配 `env(safe-area-inset-bottom)`；文字放大时容器使用 `min-height`。`fontSizeSetting` 的 17–19px 值在部分 iPhone/微信组合中仍可能属于常规显示，活动卡仅在该值达到 `20px` 时启用大字降级布局，避免正常字号把首页三列误切为单列。
- 仅在确有全屏沉浸需求的页面使用 `navigationStyle: custom`；正文顶部由状态栏和微信胶囊坐标计算，并对零值、缺失或 API 异常提供安全 fallback。固定全屏覆盖层与正文避让分离，其他页面继续使用原生导航。微信胶囊和系统状态栏不得尝试隐藏或仿制。
- 首页、发现与消息主页是暖米白独立视觉例外；其他一级 Tab 继续按各自既有规范使用统一纸纹背景及全局色彩遮罩。消息主页使用紧凑标题、浅橙系统通知卡和白色私信卡；保留自然滚动与分页，来源活动独占辅助行，窄屏时间换行，卡片不得锁定高度。正文底部预留 calc(200rpx + env(safe-area-inset-bottom))；无系统通知时明确提示入口通往“我的”，不得暗示通知中心。所有自定义导航页正文均通过动态安全区避让系统状态栏与微信胶囊。
- 弱网 8 秒后给出重试入口，不展示 CloudBase 原始错误。
- 可点击活动卡的读屏文本至少包含类型、标题、状态、时间、地点和名额信息；弹性行使用 `flex-wrap`，不得依赖固定卡片高度。
- 靠近页面底部的 `input`、`textarea` 使用 `cursor-spacing` 与 `adjust-position`，并与 Safe Area 一起做真机键盘验证。包含原生 `input` 的浮层在关闭时必须通过 `wx:if` 卸载节点，不得仅依靠 `visibility`、`opacity` 或 `pointer-events` 隐藏；部分 iOS 微信版本会让原生输入层或 placeholder 穿透显示。
- 多行提问/回答使用支持 `textarea` 的自定义底部抽屉；蒙层必须阻断背景手势，抽屉适配 Safe Area，提交失败保留输入并恢复 pending 状态。

## 性能

- Mock 自定义头像可使用微信本地沙盒路径 `wxfile://`、`http://tmp/`、`http://usr/`、`/tmp/`、`/var/`；不得把这一兼容范围扩展为任意公网 HTTP 或 `cloud://`。生产活动头像继续只消费服务端签发的 HTTPS 展示地址。
- 真机运行时插画与头像使用保留多级 Alpha 的 PNG，照片与纸纹使用非渐进式 Baseline JPEG；禁止在页面运行时重新引入 WebP，避免部分 iOS 微信版本对本地包图片静默解码失败。`wx.previewImage` 只允许直接消费白名单内的包内 PNG/JPEG；不得对这类包路径再执行 `FileSystemManager.access`，部分 iOS 微信版本会把可正常渲染的包资源误判为不可访问。`cloud://` 与 HTTPS 分别经下载接口落为临时文件，其他临时路径统一通过本地沙盒白名单与 `FileSystemManager.access` 后再预览。解析过程必须有超时、互斥锁、页面隐藏取消序号和卸载保护；错误只展示安全文案，不记录完整私有 fileID。
- 分包页面专用素材必须放在对应分包目录并使用分包内相对路径，禁止为复用方便把大图反向放入主包。主包源码预算为 `1.70MiB`，发布分包预算为 `1.20MiB`，其他单分包预算为 `1.50MiB`；无运行引用的历史素材不得留在 `miniprogram/`。整页不透明纸纹使用 Baseline JPEG，透明撕边与插画使用保留多级 Alpha 的优化 PNG，降采样必须维持原比例和透明边界。

- 列表分页；避免一次性全量 `setData` 和深层大对象。
- 自定义启动覆盖层只在一次 App Session 首次进入默认 Tab 时展示，不新增中转路由，也不拦截分享或服务通知直达。静态封面须压缩后进入主包；组件内启动图片使用可被预览包静态分析的相对路径，并优先采用 iPhone 稳定解码的 baseline JPEG/PNG。任一关键图片加载失败时只上报一次并立即关闭启动层。伪进度在首屏请求结束前不得到达 100%；达到硬超时上限时可以关闭启动层并交还页面自身的真实加载态，但不得伪造最终进度。页面隐藏、卸载或正常结束均须清理计时器并恢复 TabBar。动画子节点从无障碍树隐藏，根节点只提供稳定的一次性加载语义。透明透视素材必须保持源宽高比；元素的静态透视定位/缩放与动态落体 transform 分置父子节点，避免动画覆盖最终布局。
- 首页“正在组队 · 全城热拼”固定只展示首批最多 3 个活动，不在单屏首页原地追加、触底加载或管理后续游标。章节标题右侧“发现更多 ›”以防重复入栈的 `navigateTo` 进入 `subpackages/activity/nearby/index`；附近页必须先展示用途说明，由用户点击后才调用 `wx.getLocation({ type: 'gcj02' })`，覆盖定位中、有数据、空、拒绝/失败、服务不可用和续页失败状态，并始终提供全城列表降级入口。查看者坐标只保存在页面实例字段，隐藏/卸载即清除，不进入 `data` 或 Storage。半径固定为 1/3/5/10km，距离标签只能消费服务端 `nearby.distanceMeters`。
- 三类发布表单共用“公开会合地点（必填）”控件，通过发布分包内的高德 POI 检索页选择：拼同行回填出发集合点，拼运动回填场馆，拼饭桌回填餐厅。手动修改关联文字必须清除旧 `meetingPoint`，无有效高德 GCJ-02 POI 时拦截提交。控件下方固定说明“这是活动公开地点，用于附近发现，不会保存您的实时位置”。高德 Key 只从被忽略的本地运行配置读取，不得进入仓库。
- 活动截止计时只用于隐藏已明显截止的旧招募卡片并触发服务端事实刷新；定时延迟设置上下限，长时间等待只重新排程，不建立高频轮询。页面隐藏或卸载时必须清理计时器并使在途响应失效。
- 主包硬预算不超过 1.70MiB，发布分包不超过 1.20MiB，其余单分包不超过 1.50MiB；非关键页面与未来图片资源优先进入分包，并持续保留微信 2MiB 主包限制的安全余量。
- 不引入状态库、UI 框架或动画库；优先原生组件和小型自有组件。
