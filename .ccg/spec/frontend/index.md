# 拼吧微信小程序前端规范

## 技术边界

- 使用微信原生小程序 JavaScript，直接导入微信开发者工具运行，不依赖本地编译步骤。
- 主包只放 Tab 页面；详情、发布表单、申请管理、成团和举报使用分包。
- 页面不得直接调用 `wx.cloud.callFunction`；统一通过 `miniprogram/services/`。
- 默认启用 Mock Service，使 `touristappid` 下也能走通 MVP；切换 Cloud 模式时页面代码不变。

## 信息架构

- TabBar 固定为“发现 / 发布 / 我的”。
- 发现页使用通用活动卡片骨架，场景差异放入属性槽。
- 发布固定两步：核心匹配信息；规则、安全和成团后联系信息。
- “我的”顶部优先展示待审批、已成团和即将开始任务。
- 通知点击只接受 `MANAGE | GROUP | DETAIL` 语义目标并由本地页面白名单生成路径；未知目标降级详情，缺失 ID 返回发现页，不执行服务端或通知记录携带的自由 URL。
- 活动分享只使用公开标题与编码后的不透明活动 ID；详情未加载、参数无效、网络错误或活动下架时，分享卡片统一降级到发现页，不传播失效详情或任何 viewer/contact 字段。
- 澳门拼车发现页的一级分类固定为“全部 / 凼仔校区 / 金龙校区”三个等宽校区 Chip，不在首页展示 8 条路线 Chip；具体路线仅用于发布滚轮、行程卡片和详情。切换乘客/司机视角保留校区筛选，清除筛选同时清空校区与搜索草稿。
- 澳门校园拼车发布页只读展示固定 7 个乘客名额，司机不计入人数；发现页乘客主徽标只使用“招募中 / 已满员”，不得残留“已成团·可加入”等旧文案。
- 澳门拼车发布者与直接入团乘客都必须在页面内选择“我的行李”，选项固定为“无行李 / 小行李 / 大行李”，初始不默认选中；提交失败保留选择，成功后以服务端 `viewerMembership.luggageType` 回填。活动级旧“行李规则”不再展示或提交，历史缺失值显示“未填写”而不是推断为“无行李”。

## 状态与数据

- 服务端是业务事实来源；页面在 `onShow` 或关键动作后重新拉取，不用 EventBus 维护关键状态。
- 所有页面必须显式覆盖 loading、empty、error 和业务失效状态。
- 全局请求层已经向用户反馈的错误必须标记为 `error.handled` 后继续抛出；页面据此抑制重复 Toast 或原始文案，但仍须通过 `finally` 或安全错误分支恢复 loading、pending、submitting，并清空不可继续展示的旧业务数据。
- 业务失效状态使用稳定错误码分支，不比较展示文案；重复加载前清空旧业务数据，并用请求序号阻止过期响应覆盖新状态。
- 详情页公开问答使用独立请求序号和局部 loading/empty/error/ready 状态；问答失败不得清空活动详情或阻断申请、管理、成团等主链路。写入成功后重新拉取服务端事实，不做问答乐观插入。
- 分享冷启动先在页面 `onLoad` 防御性解析路由参数，再由页面生命周期加载公开详情；只有存在真实异步全局依赖时才建立 readiness Promise，不为同步初始化或公开读取制造空等待层。
- 服务通知直达页必须兼容单页面栈：无权限可 `redirectTo` 公开详情，不存在或下架时 `switchTab` 返回发现；不得依赖 `navigateBack`。受保护目标页需在空 ID 时结束 loading，并用请求序号丢弃离屏或过期响应。
- 提交按钮具有 pending 防重；失败保留表单和用户输入。
- 非拼车申请按钮继续说明获批占位；澳门拼车详情使用“立即加入拼车”，不得展示备注、同意勾选、等待审批或发起者批准入口。
- WXML 不执行除法等需要边界保护的展示计算；进度百分比、剩余数量和读屏文案在 JS 装饰层预计算并限制合法范围。
- 拼车加入与退出按钮只消费服务端 DTO 的 `canJoinRide`、`canLeaveRide` 与 `rideExitLocked`，不得由前端自行推导。若响应缺少布尔型 `canJoinRide`，必须 fail-closed 并提示服务版本异常，不得回退到 `RECRUITING` 或剩余名额推导。司机确认后已有成员显示静态退出锁定说明，但未满 7 人且 `canJoinRide` 为真时，新乘客入口继续开放。
- 拼车管理页不展示申请审批列表，改为展示当前容量、司机承接状态和“乘客直接加入，无需审批”说明；非拼车管理页保持原申请流。
- 拼车展示层只有 `RECRUITING` 与 `FORMED` 可按剩余名额归一为“招募中 / 已满员”；`CANCELLED`、`EXPIRED`、`IN_PROGRESS`、`COMPLETED`、`SUSPENDED` 等生命周期状态必须优先保留服务端状态语义，不得被人数覆盖。
- “我的”等聚合页每次刷新都必须生成请求序号，仅最新请求可更新页面；页面隐藏或卸载时使在途响应失效，防止旧快照覆盖取消、退出等新事实。

## 隐私与安全

- 列表和详情零登录浏览；发布、申请、我的按动作触发登录。
- 首屏不请求位置、手机号或头像权限；城市和区域手动选择。
- 联系信息不随详情加载；仅在成团页由用户主动点击后请求，首次显示一次安全确认。
- 不展示未验证的实名、信用或手机号徽章。
- MVP 不上传 UGC 图片、群二维码或举报证据图片。
- 微信隐私接口按实际动作请求，不在首屏预授权。`wx.onNeedPrivacyAuthorization` 是覆盖式监听且没有对应的 off API；用单例桥接管理当前活动组件，注册后每个请求都必须以 `agree` 或 `disagree` 结算。
- 剪贴板授权只控制 `wx.setClipboardData` 等本地能力，不进入服务端成员权限契约。拒绝或旧基础库降级时，必须保留可选中文本等真实可用的非敏感替代路径。
- 司机证件号与认证图片引用不得写入 Local Storage；上传成功后页面只保存短期 uploadId，sealed 文件地址只存在服务端。敏感写请求的本地幂等指纹必须不可包含或复原完整 payload。
- 拼车发布者与直接入团乘客必须填写受控区号的本人电话；电话输入失败时保留、提交成功或页面销毁时清空，不进入草稿、Local Storage、分享参数、日志或公开详情。成员电话列表仅在当前承接司机的详情视角按需加载，页面隐藏、卸载、切换乘客视角或取消承接时立即清空，并用独立请求序号丢弃晚到响应。

## 视觉与可访问性

- 品牌主色使用独立绿色 `#16A36A`，避免暗示与微信官方存在隶属关系。
- 场景色：拼车蓝、拼商品橙、拼搭子紫；状态不能只靠颜色表达。
- 项目使用微信原生 `tabBar` 时，图标缩放与抗锯齿由客户端控制；不要为不存在的自定义 TabBar 添加 `image-rendering` 或 GPU transform 补丁。激活/未激活图标应在源文件阶段统一画布、视觉尺寸和几何母版。
- 正文最小 `28rpx`，辅助文字最小 `24rpx`；交互热区不小于约 44px。
- 固定底部操作区适配 `env(safe-area-inset-bottom)`；文字放大时容器使用 `min-height`。
- 仅在确有全屏沉浸需求的页面使用 `navigationStyle: custom`；正文顶部由状态栏和微信胶囊坐标计算，并对零值、缺失或 API 异常提供安全 fallback。固定全屏覆盖层与正文避让分离，其他页面继续使用原生导航。微信胶囊和系统状态栏不得尝试隐藏或仿制。
- 弱网 8 秒后给出重试入口，不展示 CloudBase 原始错误。
- 可点击活动卡的读屏文本至少包含类型、标题、状态、时间、地点和名额信息；弹性行使用 `flex-wrap`，不得依赖固定卡片高度。
- 靠近页面底部的 `input`、`textarea` 使用 `cursor-spacing` 与 `adjust-position`，并与 Safe Area 一起做真机键盘验证。
- 多行提问/回答使用支持 `textarea` 的自定义底部抽屉；蒙层必须阻断背景手势，抽屉适配 Safe Area，提交失败保留输入并恢复 pending 状态。

## 性能

- 列表分页；避免一次性全量 `setData` 和深层大对象。
- 自定义启动覆盖层只在一次 App Session 首次进入默认 Tab 时展示，不新增中转路由，也不拦截分享或服务通知直达。静态封面须压缩后进入主包；组件内启动图片使用可被预览包静态分析的相对路径，并优先采用 iPhone 稳定解码的 baseline JPEG/PNG。任一关键图片加载失败时只上报一次并立即关闭启动层。伪进度在首屏请求结束前不得到达 100%，页面隐藏、卸载或正常结束均须清理计时器并恢复 TabBar。动画子节点从无障碍树隐藏，根节点只提供稳定的一次性加载语义。透明透视素材必须保持源宽高比；元素的静态透视定位/缩放与动态落体 transform 分置父子节点，避免动画覆盖最终布局。
- 发现页分页的 replace 请求必须生成新序号并抢占旧 replace/append；append 只能复用当前查询序号、透传不透明游标并按实体 ID 去重。续页失败保留已有内容，在页尾提供 loading、重试、已到底三种互斥状态。
- 活动截止计时只用于隐藏已明显截止的旧招募卡片并触发服务端事实刷新；定时延迟设置上下限，长时间等待只重新排程，不建立高频轮询。页面隐藏或卸载时必须清理计时器并使在途响应失效。
- 主包目标小于 1.5MB，非关键页面与未来图片资源进入分包。
- 不引入状态库、UI 框架或动画库；优先原生组件和小型自有组件。
