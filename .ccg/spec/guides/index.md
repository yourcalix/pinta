# 拼吧通用开发指南

- 先修改测试或补充失败用例，再实现业务规则。
- 一个函数只承担一个明确动作；跨实体变更放在领域服务和事务中。
- 所有时间保存为 ISO 8601 UTC 字符串，页面按本地时区展示。
- 所有 ID 为不透明字符串；不要从 ID 推断类型或时间。
- 所有环境配置提供无密钥示例，真实 AppID、环境 ID、模板 ID 不进入仓库。
- 微信开发者工具的真实 AppID 放入被忽略的 `project.private.config.json`；公共 `project.config.json` 保留 `touristappid`，利用私有配置的更高优先级完成本地覆盖。
- 微信平台门禁必须区分“明确违规/能力受限”和“备案、认证、主体规划”：前者阻断真实环境切换，后者可在类目允许时作为上线前规划项；延期处理不等于通过。
- 功能可以在 Mock 模式演示，但交付文档必须清楚区分 Mock 与真实 CloudBase 行为。
- 账号失效等全局反馈应在统一请求出口处理：清理当前会话作用域、用共享 Promise 合并并发原生弹窗，并继续抛出带 `handled` 标记的错误，保证页面状态收尾正常执行；不得清空其他结果未知写请求的幂等键。
- 每个完整 G 阶段在测试、CCG 分域复审、任务归档和本地提交全部完成后，推送到用户指定的 GitHub 远程仓库；阶段内切片只做本地提交。默认只执行普通 push，不强推、不覆盖远程历史，并在交付时报告远程分支与提交哈希。
- 当前阶段交付远程为 `origin`（`https://github.com/yourcalix/pinta.git`），目标分支为 `main`；若远程已有不同历史或分支保护导致普通 push 被拒绝，停止并向用户报告，不使用强推绕过。
- 每次交付前运行：自动化测试、JavaScript 语法检查、项目结构校验、关键流程手工清单。
- 给无法访问仓库的外部审查模型提供代码摘录时，不得省略与审查主题相关的事件绑定、状态分支和属性；若为等价缩写，应明确哪些属性已省略，避免把上下文缺失误判成代码缺陷。
