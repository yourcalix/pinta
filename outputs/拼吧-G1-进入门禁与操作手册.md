# 拼吧 G1 进入门禁与操作手册

版本：1.0
日期：2026-08-23

## 1. 当前结论

代码侧 G0 已交付，但当前本地没有 `project.private.config.json`，真实 AppID 尚未接入，因此门禁预期为 `BLOCKED`。这不是业务代码回归，而是进入真实账号联调前尚未完成的外部配置。

## 2. 门禁结果

| 结果 | 退出码 | 含义 | 是否可进入 G1 |
| --- | ---: | --- | --- |
| `PASS` | 0 | 自动项通过，全部阻断性人工证据齐全 | 可以创建 G1 任务 |
| `MANUAL` | 3 | 自动项正常，但仍缺后台或真机证据 | 不可以 |
| `BLOCKED` | 1 | 配置、Git 隔离、明确失败或证据结构异常 | 不可以 |

门禁脚本只读运行，不修改文件、不联网、不登录微信账号、不调用 CloudBase，也不会输出 AppID、环境 ID、模板 ID、联系人或证据正文。

## 3. 第一步：本地接入真实 AppID

1. 复制 `project.private.config.example.json` 为 `project.private.config.json`。
2. 仅在新建的私有文件中填写真实 AppID。
3. 公共 `project.config.json` 必须继续保留 `touristappid`。
4. 运行 `git status --short`，确认私有文件没有出现。
5. 在微信开发者工具重新打开项目，确认实际使用的是对应真实账号。

不要在聊天记录、截图、提交记录或人工证据 JSON 中填写完整 AppID。门禁只判断文件存在、JSON 可解析、形态有效、已忽略且未跟踪。

## 4. 第二步：完成微信后台阻断项

### 4.1 账号成员

- 管理员、开发者、体验成员名单与当前协作人员一致。
- 移除不再参与项目的成员。
- 不共享管理员微信、密码、验证码或其他登录凭据。

### 4.2 服务类目

- 类目必须覆盖实际开放的拼车同行、商品凑单和活动搭子能力。
- 若平台审核反馈某一场景不属于已选类目，先关闭该入口，再决定是否补充资质或调整范围。
- 不通过更换模糊文案规避真实业务属性。

### 4.3 隐私保护指引

- 声明用户主动填写的昵称、城市、兴趣、活动、申请、联系方式、退出/取消和举报信息。
- 明确联系方式仅在成团后向有效成员按需披露，并记录访问审计。
- 剪贴板用途应描述为：用户主动点击复制时，将已经显示的联系信息写入剪贴板。
- 不声明当前未使用的手机号授权、精确位置、头像、通讯录、相册、麦克风或二维码能力。

### 4.4 测试 CloudBase 环境

- G1 前只要求测试环境已创建，并明确负责人。
- 不要求本阶段把环境 ID 写入代码或人工证据。
- 生产环境可以延后到上线准备阶段，但必须与测试数据彻底隔离。

## 5. 第三步：完成真实设备矩阵

使用 `outputs/拼吧-G0-真实设备验收记录模板.md`，至少完成一台 iPhone 和一台 Android。截图、录屏和测试账号说明保存在本机 `g1-readiness-evidence/` 或仓库外的受控位置；该目录已被 Git 忽略。

模拟器、`touristappid`、开发者工具强制展示弹窗均不能替代真机证据。

## 6. 第四步：填写私有人工证据

复制模板：

```bash
cp g1-readiness.manual.example.json g1-readiness.manual.json
```

每个阻断项只有同时满足以下条件才可写为 `PASS`：

- `status` 为 `PASS`；
- `checkedAt` 是有效 ISO 8601 时间；
- `checkedBy` 非空；
- `evidence` 至少包含一个本地证据引用。

明确失败写 `FAIL`；尚未完成保持 `PENDING`。不要把完整 AppID、环境 ID、模板 ID、密码、验证码、openid 或真实联系方式写入证据文件。

## 7. 第五步：执行门禁

```bash
npm run g1:readiness
```

该命令先运行完整测试和项目检查，再输出结构化 JSON。最终唯一规则是：

```text
ALLOW_G1_SWITCH = result === "PASS"
```

只要仍有 `MANUAL` 或 `BLOCKED`，就不能把 `useMock` 改为 `false`，也不能把测试环境 ID 或订阅模板 ID 写入项目配置。

## 8. 建议项

以下内容会显示在报告中，但不阻断创建 G1 任务：

- 内容安全接口申请入口与负责人已备案；生产环境实际启用属于 G1 硬门槛。
- 订阅消息模板申请已提交；审批结果在 G3 通知链路前必须取得。
- 生产 CloudBase 环境已规划或创建；上线前必须完成隔离验收。
